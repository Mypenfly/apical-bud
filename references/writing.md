# 推演的写法

方法主干见 `SKILL.md`。这份文件只在你要**写**推演点、写结论、写提问的时候读。

## 一、一个推演点长什么样

下面是完整的一例（材料来自一次真实讨论：低成本 agent 系统）。注意它在做什么：先摆出前提的来处，再推，再落一条**能被反驳**的结论，再说它在什么情况下不成立，最后交出下一个问题。

```markdown
---
point: 02
title: 该减少劣质还是增加优质
status: open
answers: [Q-01.2]
from: [D-01.1, F-002]
---
## 问题
Q-02.1 提高上下文密度，该从减少劣质片段入手，还是从增加优质片段入手？

## 已知
- [结论 D-01.1] 成本的杠杆在上下文的量与质，不在输出长度。
- [事实 F-002] 能一眼认出的劣质特征只有浅层那几类（重复、套话、未经验证的结论、黑话与比喻）；
  需要上下文才能判断的那些，人和模型都认不出。

## 推论
- 减少劣质片段要求先认出它，而"认出"本身比原问题更难——这条路要系统先解决一个更难的问题。
- 增加优质片段不需要识别坏内容，只需要在事情将要变坏的那一刻给出基于事实的判断。
- 所以两条路不是并列的两个选项：一条要求一个尚未具备的能力，另一条只要求一个已经观察到的动作。

## 结论
D-02.1 只做"增加优质"这一侧：在错误将要固化时注入基于事实的判断；放弃"清理已有上下文"。

## 反过来
- 若注入总是晚于错误的固化，这条不成立。
- 若上下文的劣化主要来自与判断无关的噪声，清理仍然必要。

## 生出的问题
Q-02.2 谁来判断"将要固化"？判断的依据从哪来？（去向：待答）

## 用户
> "减少已经在上下文中的劣质token是不现实的，而增加优质token是可行的。"
```

**它为什么算推演**：结论不是从结论里抄出来的，是**推**出来的——先建立"两条路要求的不是同一种能力"这个区别，结论才站得住；而且它排除了东西（清理这条路），还说得出自己在什么情况下倒掉。

## 二、四种不该出现的形状

**① 把同一个决定写两遍。** 先写一条"候选：按范围隔离"，再写一条"定论：按范围隔离"。两条的正文几乎一样，只是标题换了。这不是"先摊候选再挑"，是把一句话抄了一次。**一个结论只写一次**；被放弃的那条路写在「## 反过来」或一句"这条排除了什么"里就够了。

**② 成对生长。** 每加一层就配三个节点（两条候选 + 一条定论），编号连着长，`D-03.1 → D-03.2 → D-03.3` 内容依次递减。**推演点的数量由问题决定，不由进度决定**：一个点摊不出东西，就写"这一点没有新的可推，因为…"然后 `closed`。

**③ 结论是形容词串。** "一个优雅的、可扩展的、面向未来的调度层"——用户无从否起。改成能被反驳的命题："调度层只认依赖登记，不做问答式协商；被它唤醒的一方无法区分上游的对与错。"

**④ 用公文语气汇报进度。** "本轮已完成候选摊开，下一步将推进定论。"——这句话里没有前提、没有结论，是纯进度噪音。**写"现在链上最紧的张力是什么"**，不写"我完成了什么"。

## 三、措辞对照

| 不要写 | 改写成 |
|---|---|
| 本阶段完成 / 已通过门禁 | （删掉，或写"这一点结掉了：D-03.1"） |
| 落盘 / 留痕 / 产物清单 | 写进 `derivation/03-….md` |
| 我需要确认一下你的倾向 | 这两条不能同时成立，你放弃哪一条、为什么？ |
| 综合来看，建议方案 A | 我押 A，因为…；它可能在…处错 |
| 基于行业最佳实践 | 因为 <出处> 的 <事实>，所以…… |
| 这样可以吗？ | （先给出论证，再问那个非答不可的问题） |
| 高风险 / 优雅 / 能力强 | 说具体后果：这一撤，D-02.1 的前提没了 |

## 四、常见病症

| 症状 | 病灶 | 怎么改 |
|---|---|---|
| 一直在加文件，链上没有新东西 | 把"记录"当成了"产出" | 删掉没有结论的点；一个点必须落一条能被反驳的话，或明说推不动 |
| 讨论绕回开场那句话 | 用户给的结论被当成前提用了 | 把它登记成"待推导的结论"，从需求正推一遍；推不到就说差在哪一跳 |
| 每轮都问一个选择题，用户每次都选我推荐的那条 | 我在用选项代替论证 | 摊开张力、说出我的赌注；把"用户的理由"要出来 |
| 结论都对，但没人能拿它去做什么 | 没有 `## 接缝与边界` 与「要落地必须先定的事」 | 补上部件、传什么、什么算失败 |
| 悬置的问题越积越多 | 没有区分"待答"和"悬置" | 待答＝还没问到；悬置＝知道什么事实能解开、但现在拿不到（可能很久）。悬置必须写出解锁条件 |
| 用户不在场，认领列只能整列写"待答"，推演看起来没跑偏也没落点 | 把"没有判断"和"没有用户"混在一起 | 认领列写「候选：<我的判断>（待答）」；等用户回来再让他把候选改成 核心/次要/不算 |
| 问题连"去向"都没写 | 悄悄丢了 | 三个里写一个：待答／悬置／由推演点 NN 回答 |
| 事实是"我记得""一般认为" | 没写出处 | 补 `出处` 与 `等级`；补不上就写进「没查的」 |
| 结论读起来都对，但没人能拿它做事 | 停在印象层 | 给数量、可算的代理，或量级；三样都给不出，这条还不算推出来 |

## 五、落笔前的三个自检

1. **这条结论能被什么反驳？** 答不出来，它不是结论，是形容词。
2. **它的前提在哪？** 前提指向的编号必须真的存在（`F-`/`D-`/`Q-`/`model`/`seed`/`用户`）；假设不许单独支撑结论。
3. **它生出了什么问题？** 一条结论生不出问题，通常意味着它没推进什么——那就把它删掉。
