# 推演的写法

方法主干见 `SKILL.md`，推演的循环（一个节点走一遍五问、未定项必须清零）见 `loop.md`。这份文件只在你要**写**推演节点、写结论、写实验件、写提问的时候读。

## 一、一个推演节点长什么样

下面是完整的一例（材料来自一次真实讨论：低成本 agent 系统）。注意它在做什么：先摆出前提的来处，再推，再落一条**能被反驳**的结论，再说它**怎么落到机制上**、在什么情况下不成立，最后交出下一个问题与**还没确定的事**。

```markdown
---
point: 02
title: 该减少劣质还是增加优质
status: open
what: 优质 / 劣质 token
line: R-02
undecided: 1
answers: [Q-01.2]
from: [D-01.1]
---
## 问题
Q-02.1 提高上下文密度，该从减少劣质片段入手，还是从增加优质片段入手？

## 已知
- [结论 D-01.1] 成本的杠杆在上下文的量与质，不在输出长度。
- [事实 F-002] 能一眼认出的劣质特征只有浅层那几类（重复、套话、未经验证的结论、黑话与比喻）；
  需要上下文才能判断的那些，人和模型都认不出。

## 推论
- 减少劣质片段要求先认出它，而"认出"本身比原问题更难——这条路要系统先解决一个更难的问题。
- 增加优质片段不需要识别坏内容，只需要在事情将要变坏的那一刻给出基于事实的判断。
- 所以两条路要求的能力不同：一条要求一个尚未具备的能力，另一条只要求一个已经观察到的动作。

## 结论
D-02.1 只做"增加优质"这一侧：在错误将要固化时注入基于事实的判断；放弃"清理已有上下文"。

## 怎么落机制
注入这件事落到机制上是：只读异常点附近的片段；在错误将要固化时触发；注入内容必须带出处。
谁来判断"将要固化"还指不出来——这就是下面那条未定项。

## 反过来
- 若注入总是晚于错误的固化，这条不成立。
- 若上下文的劣化主要来自与判断无关的噪声，清理仍然必要。

## 生出的问题
Q-02.2 谁来判断"将要固化"？判断的依据从哪来？（去向：由推演节点 03 回答）

## 未定项
- 判断的触发者与时机没定；由推演节点 03 回答。

## 用户
> "减少已经在上下文中的劣质token是不现实的，而增加优质token是可行的。"
```

**它为什么算推演**：先建立"两条路要求的能力不同"这个区别，结论才站得住，而且它排除了东西（清理这条路），说得出自己在什么情况下倒掉，**还指到了机制、并把暂时指不出的那一点写成了未定项**。

**一个节点走一遍五问**（`what / parts / explain / how / new`）——这份骨架把五问落在了小节里：

| 五问 | 落在哪 |
|---|---|
| `what` 命名 | frontmatter 的 `what:` |
| `parts` 组成 | `## 已知` 里那几块材料 + `## 推论` 的第一条 |
| `explain` 为什么 | `## 推论` 的"所以……"与"它排除了哪条路" |
| `how` 怎么落机制 | `## 怎么落机制`（指不出就写"还指不出，因为……"） |
| `new` 新概念／新问题 | `## 生出的问题` + `## 未定项` |

分节写 `## what` / `## parts` / `## explain` / `## how` / `## new` 同样可以。**形式随你，五问不能少。**

## 二、六种不该出现的形状

**① 把同一个决定写两遍。** 先写一条"候选：按范围隔离"，再写一条"定论：按范围隔离"。两条的正文几乎一样，只是标题换了。摊候选要的是两条不同的路，这里只是把一句话抄了一次。**一个结论只写一次**；被放弃的那条路写在「## 反过来」或一句"这条排除了什么"里就够了。

**② 成对生长。** 每加一层就配三个节点（两条候选 + 一条定论），编号连着长，`D-03.1 → D-03.2 → D-03.3` 内容依次递减。**节点数量由问题决定，不由进度决定**：一个节点摊不出东西，就写"这一点没有新的可推，因为…"然后 `closed`。

**③ 结论是形容词串。** "一个优雅的、可扩展的、面向未来的调度层"——用户无从否起。改成能被反驳的命题："调度层只认依赖登记，不做问答式协商；被它唤醒的一方无法区分上游的对与错。"

**④ 用公文语气汇报进度。** "本轮已完成候选摊开，下一步将推进定论。"——没有前提、没有结论，纯进度噪音。**写"现在链上最紧的张力是什么"。**

**⑤ 未定项只增不减。** 每个节点都写了新的 `## 未定项`，一个也不关；节点数一路加、未定项一路涨。单看每个节点都合规，整棵树收不了尾。**节点收工前问一句：认领的关掉了没有、长出几个新的。** 只增不减就明说没在收敛、卡在哪一条上。

**⑥ 实验只为证明自己。** 跑了一个能跑通的最小例子，结论写"已验证可行"——没有任何一种结果会让理念失败。**没写杀判据的不算实验，算演示。** 跑之前先写死"什么结果会杀死这个理念"；结果回来了写"它让哪条结论变成什么"，**推翻了就写推翻**。

## 三、措辞对照

| 禁止写 | 改写成 |
|---|---|
| 本阶段完成 / 已通过门禁 | （删掉，或写"这一点结掉了：D-03.1"） |
| 落盘 / 留痕 / 产物清单 | 写进 `derivation/03-….md` |
| 我需要确认一下你的倾向 | 这两条不能同时成立，你放弃哪一条、为什么？ |
| 综合来看，建议方案 A | 我押 A，因为…；它可能在…处错 |
| 基于行业最佳实践 | 因为 <出处> 的 <事实>，所以…… |
| 这样可以吗？ | （先给出论证，再问那个非答不可的问题） |
| 高风险 / 优雅 / 能力强 | 说具体后果：这一撤，D-02.1 的前提没了 |
| 通过合理的架构设计 | 谁读什么、什么时候读、拿到什么；指不出就写"还指不出，因为…" |
| 已验证可行 | 证实了什么、推翻了什么、还剩什么没验证 |
| 未定项：待补充 | 一条一行，每条后面写"什么事实能解开" |

## 四、推演纪律：每一步都由上一步生出来

**反例**（需求收集）：

> 问：你现在用的是哪套系统？它哪里让你不满意？
> 用户列了五条不满 → 记成 `D-02.1 我们要解决这五条`。

没有前提、没有推论，结论是用户的话换了个说法；推演一步都没动，只是把抱怨誊清了。下一轮你还会问"那你最在意哪一条"，第三轮再问"你希望它变成什么样"——**这是需求收集。**

**正例**：

> `Q-01.2` 前缀复用率为零的地方没法设计，为高的时候又不需要设计——那"省钱"到底做在哪？
> 已知：[结论 `D-01.1`] 命中是同一批输入第二次被用到时的折扣；[事实 `F-003`] 只有前缀相同才算命中。
> 推论：既然折扣来自"同一批内容被再次用到"，能设计的就只有"让哪些内容在多次调用之间保持不变"；这条排除了"把上下文写得更精炼"这类与位置无关的做法。
> 结论 `D-02.1` ……（可被反驳）
> 生出的问题 `Q-02.2` ……（由这条结论自己生出来）

区别在三点：正例的**前提**是上一步的结论与一条外部事实；**推论**排除了东西；**下一个问题**从结论里长出来。

**想谈现有系统时**：把它当外部事实去查——读它的源码、文档、日志，跑一次实测——写进 `facts.md` 的 `F-` 条目。用户抱怨进 `seed.md`，用来说明"为什么现在要做这件事"；它推不出结论。**查到的进 `facts.md`，推演节点里写"这条事实让哪条结论变成什么"**——把测量报告写成推演节点，是这棵树最容易走上的偏路。

## 五、常见病症

| 症状 | 病灶 | 怎么改 |
|---|---|---|
| 一直在加文件，链上没有新东西 | 把"记录"当成了"产出" | 删掉没有结论的节点；一个节点必须落一条能被反驳的话，或明说推不动 |
| 讨论绕回开场那句话 | 用户给的结论被当成前提用了 | 把它登记成"待推导的结论"，从需求正推一遍；推不到就说差在哪一跳 |
| 每轮都问一个选择题，用户每次都选我推荐的那条 | 我在用选项代替论证 | 摊开张力、说出我的赌注；把"用户的理由"要出来 |
| 结论都对，但没人能拿它去做什么 | 没有 `## 接缝与边界` 与「要落地必须先定的事」 | 补上部件、传什么、什么算失败 |
| 悬置的问题越积越多 | 没有区分"待答"和"悬置" | 待答＝还没问到；悬置＝知道什么事实能解开、但现在拿不到（可能很久）。悬置必须写出解锁条件 |
| 用户不在场，认领列只能整列写"待答"，推演看起来没跑偏也没落点 | 把"没有判断"和"没有用户"混在一起 | 认领列写「候选：<我的判断>（待答）」；等用户回来再让他把候选改成 核心／检验条件／不算 |
| 问题连"去向"都没写 | 悄悄丢了 | 三个里写一个：待答／悬置／由推演节点 NN 回答 |
| 事实是"我记得""一般认为" | 没写出处 | 补 `出处` 与 `等级`；补不上就写进「没查的」 |
| `facts.md` 里写着"用户说他以前……" | 把用户当成了信息来源 | 用户的话是需求与判断（种子 / 推演节点的 `[用户]`）；`facts.md` 只收外部信息 |
| 回复只有"已写入 `derivation/03-….md`，你看一下" | 用文件代替回答 | 先把内容在对话里说一遍（结论、代价、反例、要问的那个问题），再说它记到了哪个文件 |
| 一轮里问了用户三个"你以前是不是……"（禁止这样问） | 把创造任务做成了满意度问卷 | 他的过往体验一律不进 `facts.md`；除非需求本身关于体验，去查外部信息 |
| 第 2 个节点开始就在谈别的题目 | 另起了一个话题 | 每个节点都要 `answers:` 上一步的问题，或 `from:` 上一步的结论（`D-`） |
| 结论是"用户列的不满清单"换个说法 | 把需求收集当论证 | 抱怨进 `seed.md`；现有系统当外部事实去查，写成 `F-` 条目 |
| 一条需求线连吃四个节点，另一条一个都没有 | 树的轨道偏了 | 每条线都要有节点（`line: R-0x`）；核心问题必须压住每一条线——见 `loop.md` 的偏离形状二 |
| 每个节点的 `from` 里都躺着这一步刚测出来的那条事实 | 拿最新调研当引子，结论跟着测量跑 | `from` 只放结论 `D-`；事实进 `## 已知`，测量产物进 `facts.md`——见 `loop.md` 的偏离形状三 |
| 种子里写了三条检验条件，一条也没有节点在验它 | 担保只是写给人看的 | 每条检验条件都要有 `line:` 指向它的节点；不想推就把那条删掉 |
| 连着几个节点没有新概念，结论都是"某笔账划不划算" | 在做核算，没在推演 | 一步的产物是概念：它解释了哪条拆分、生出了什么问题 |
| 一步里回答了三个问题 | 想一次推完 | 一步一个问题；下一个问题由这一步的结论生出来 |
| 结论读起来都对，但没人能拿它做事 | 停在印象层 | 给概念一个能算的说法，或给量级；两样都给不出，这条还停在印象里 |
| `probe/` 下的脚本写好了，讨论会话自己就跑起来了 | 把实验当成了推演的一部分 | 讨论这一层只产出实验文件；用户换标准模式会话去跑，把结果带回来 |

## 六、落笔前的四个自检

1. **这条结论能被什么反驳？** 答不出来，它是形容词。
2. **它的前提在哪？** 前提指向的编号必须真的存在（`F-`/`D-`/`Q-`/`model`/`seed`/`用户`）；假设禁止单独支撑结论。
3. **它落到哪个机制上了？** 指不出就写"还指不出，因为……"。
4. **它生出了什么问题，又留下了几项未定项？** 一条结论生不出问题，通常意味着它没推进什么——那就把它删掉；未定项只增不减，说明这棵树在铺摊子。
