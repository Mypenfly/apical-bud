# 体检与文件清单

方法主干见 `SKILL.md`。这份文件管三件事：九个文件各装什么、体检查什么、怎么跑。

## 一、九个文件

| 文件 | 装什么 | 谁写 |
|---|---|---|
| `seed.md` | 用户原话、一句话需求、**需求线（拆词 + 角色）**、**核心与放弃代价**、**核心问题**、非目标、什么叫成了、被否的表述、`needs_probe` | 我写，用户确认 |
| `facts.md` | **只收外部信息**：文档、源码、论文、数据、账单、实测。`## F-001` + 出处 + 等级（E1 文档源码／E2 实测／E3 二手）+ 用途；末尾一节「没查的」 | 我写 |
| `derivation/NN-<词>.md` | **推演节点**，一点一文件；序号即推演顺序，最后一个节点就是现在的进度 | 我写 |
| `model.md` | **顶芽**：名字、一句话、概念图、组成、接缝与边界、确定了什么／还没确定什么／反转 | 我写，用户认 |
| `build/01-判据.md`、`02-方案.md`、`04-选型.md` | 判据先写，方案后看，`03-实验.md` 按需 | 我写 |
| `probe/` | **实验件**：能直接跑的脚本 + `README.md`（跑法、回答哪个 `Q-`、杀判据、结果记录处） | 我写，**用户自己去跑** |
| `handoff.md` | **果实**：自包含交接件 + **验证状态** | 我写 |
| `map.md` | 进度、需求线覆盖、概念链、未定项 | **工具生成，禁止手写** |
| `glossary.md` | 术语：`- **词**：一句人话定义`（附「曾用名」「不用的词」） | 随用随记 |

**只收外部信息**：`facts.md` 里出现"用户说他以前……"就是违规——用户的话进 `seed.md` 与节点的 `[用户]`。

## 二、开工次序

1. **先立种子**：一句话需求 → 需求线（拆词 + 角色）→ 核心与放弃代价 → 核心问题。**再出去调研。**
2. **第一件事读 `map.md`**，没有就跑 `apical_check action=map`。
3. 项目里还没有讨论根，照 `templates/` 起四件：`seed.md`、`facts.md`、`glossary.md`、第一个节点（`derivation/01-….md`）。
4. 调研只回答种子里已经写下的问题。调研发现该拆成别的线，**先改种子、说清为什么改**，再往下走。
5. 用户开口就给过结论：登记成**待推导的结论**，从需求正推一遍——推得到才被论证，推不到就是假设或竞争概念，并说清差在哪一跳。**禁止拿它当前提直接用。**

## 三、顶芽（`model.md`）要成形

`model.md` 的硬项只有两个：`name:` 与 `## 一句话`（≤60 字）。其余小节：

- `## 概念图`：哪个概念从哪个概念长出来、各自解释了哪个现象（`map.md` 里那份由工具生成，这份是底稿）。
- `## 它由什么组成`／`## 接缝与边界`／`## 确定了什么`（逐条带 `D-`）／`## 还没确定什么`（带 `Q-` + 解锁条件）／`## 反过来`／`## 反转：什么情况下这棵树不成立`／`## 要落地必须先定的事`。
- `## 还没确定什么` 空了，或每条都写明什么事实能解开、现在拿不到，才写 `status: settled`；**`settled` 之后才动 `build/`**。

## 四、技术选型四个文件

| 文件 | 装什么 |
|---|---|
| `01-判据.md` | `## K-01` + `要满足／来源／硬约束`；来源指回 `D-`/`Q-`/`model` |
| `02-方案.md` | `## O-01` + `组合／证据等级／满足／拒绝理由／复活条件`；外加一个「什么都不做／最小方案」对照项 |
| `03-实验.md`（按需） | 跑过哪些实验、每个实验什么算证实／算杀死、结论：证实了什么、推翻了什么、还剩什么没验证 |
| `04-选型.md` | 选定方案／判据对照／拒绝理由汇总／实验与证伪／退出成本与迁移／未验证假设 |

**实验是这棵树唯一能证伪自己的地方。** 理念自洽只说明它**说得通**，不说明它**成立**。要不要实验在种子里定（`needs_probe: yes | no`）；不设实验是合法选择（纯选择题、纯外部信息题），**但要在 `04-选型.md` 写一句为什么不需要**。

**这一层禁止跑实验。** 只做两件事：**产出实验文件**，让用户**换一个标准模式会话去跑**，把结果带回来。讨论会话的长上下文跑实验又慢又不准，标准模式会话能直接改代码、连着迭代。

**一个实验件**：**只回答一个问题**（文件头写死回答哪个 `Q-`；回答两个，结果就说不清是谁造成的）／**跑之前先写杀判据**（什么结果会杀死这个理念；**没写杀判据的不算实验，算演示**——演示只会证明我对）／**自带 `README.md`**（三行跑法：零依赖、不联网、不写项目外的东西）／**结果由用户带回来**（进 `facts.md` 的 `F-`，E2 实测；节点里写"它让哪条结论变成什么"；按结果更新 `model.md` 的「反转」）。**推翻了就写推翻**，一次成功的证伪比十个确认值钱。

需求被证伪是合法结局：实验说明这件事做不到、或代价高于收益，收进 `handoff.md` 的「明确不做」与 `model.md` 的「反转」。**省下的实现成本就是它的成果，禁止为留住这棵树而软化实验结果。** 模板见 [`../templates/probe.md`](../templates/probe.md)。

## 五、果实

`handoff.md` 自包含：一句话、内联的概念模型、选定组合、判据、明确不做、验收、第一件事、给接收会话的提示词、**验证状态**。

- **已证实**（有 E2 实测撑着）：直接照着实现。
- **已被推翻**（结果与推演相反）：交接件里写明，**禁止静默改掉**。
- **未验证**（只有推演与二手事实）：实现时的第一件事就是验它。

**果实是两样：`handoff.md` 和 `probe/`。** 少一样，接收方都要重新猜一遍。实现阶段发现的问题回到这棵树、记进 `facts.md`，禁止在实现会话里悄悄改概念。

## 六、体检

```bash
node scripts/check.mjs --root design/<slug>        # 人读
node scripts/check.mjs --root design/<slug> --json # 机器读
node scripts/check.mjs --root design/<slug> --map  # 顺手写出 map.md
node scripts/check.mjs --cwd .                     # 自动发现讨论根
node scripts/check.mjs --trees                     # 列出项目里的全部讨论根
```

DSH 里用 `apical_check` 工具（`check` / `map` / `trees`）。退出码 **0 = 齐**（可能有警告），**1 = 缺件**。它同时是模块：`import { check, renderReport, buildMap, discoverRoots } from './scripts/check.mjs'`。

**硬项只有组成成分与非空**：种子各节（含需求线、**核心恰好一条**）、事实与术语表、有没有推演节点、节点的「问题」「结论」空不空、模型与选型文件若存在是否成形、实验件有没有要回答的问题与杀判据。

**其余一律只是警告**：检验条件超过 3 条、检验条件没有节点在验、未定项连着几处只增不减、某条线没有节点、连着四个节点同一条线、`from` 里出现事实、编号指向不存在、悬置没写解锁条件、判据缺来源、方案早于判据、说了要实验却没有实验件……

它不判阶段、不推进、不拦讨论；`map.md` 由它生成。

## 七、旧形状

v1 形状的讨论根（`state.json` / `layers/` / `concept/`）原样保留、可读、不迁移；v1.5 形状（多条平权需求线、`step:` 标六个循环位置、没有未定项）同样读得懂、不报缺件。按这一版继续，就在同一项目里新开一个讨论根，并在新 `seed.md` 写一句「与已有树的关系」：继承了什么、推翻了什么。
