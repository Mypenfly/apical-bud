# S2：推演（逐层生长）

> **落盘时机**：本阶段谈定的任何内容，都先在对话里说清楚、拿到你的答复，再写进文件。**提案不落盘**——文件是留痕，不是介质。

目标：让主干从根系上长出来。**每个概念节点都必须是从已有内容推出来的**，调研只是肥料。

这一阶段取代了"头脑风暴三个候选"。区别不在形式，而在**每一条都必须有父节点**：灵感可以被讨论，但只有能说清"从哪儿推出来的"才能进 `derivation/`。

> **与 S3 的分工**：这里推出来的是**主张**（要做到什么、为什么）。**别在这里给理念起名**——名字是 S3 收敛的产物；也别把机制写成理念（"挑现成的、可配置"是机制，不是气质）。

## 一节主干的写法

节点文件 `derivation/N-00N-<slug>.md`，四个必写项：

| 小节 | 内容 | 门禁 |
|---|---|---|
| `from: [L-001]`（frontmatter） | 父层或父节点，必须存在 | 检查存在性 + 祖先链通到种子 |
| `## 推演` | 推理链：因为 <父的判据> → 所以 <这个主张> → 因为 <这个主张> → 所以 <将推出什么> | 非空 |
| `## 反例` | 什么情况下这条推演不成立 | 保留节点必须非空 |
| `## 调研佐证` | 来源 + 等级（E1 文档 / E2 实测 / E3 二手），没有就写"无（纯推演）" | `evidence:` 必须是 E1/E2/E3/无 |
| `## 淘汰理由` | 与哪个竞争节点冲突、被什么否掉 | 淘汰节点必须非空 |

`status: kept`（保留）/ `dropped`（淘汰）。淘汰的节点**不删**：它是树上被剪掉的枝，半年后是"为什么不选另一条路"的唯一答案。

## 推演优先，调研为辅

调研是肥料：它供给前提、检验假设、提供反例来源，但**不能直接产出概念**。

| 允许 | 不允许 |
|---|---|
| "调研发现 X 平台不支持 Y，因此这一层的实现路径只能是 Z"（前提） | "因为某项目用了 Z 并成功了，所以我们的理念是 Z"（结论搬运） |
| "我用 30 行原型验证了这条推演在数据量 1 万时成立"（E2 佐证） | "文档说它很快，所以推演成立"（E1 当结论） |
| "调研发现一个反例，推演需要加边界条件"（修正） | 把调研到的新概念直接插进 `derivation/` 而不挂父节点（孤儿节点，门禁拒绝） |

**冲突时以推演链为准，回上层修正**：如果调研事实与某条推演冲突，正确动作是回到那个节点的父层，问"是分层错了，还是这条推演漏了条件"，而不是把调研结论硬塞进顶芽。

## 生长顺序

**逐层推进，不要一次长满。**

1. 挑一个层（通常是最靠近种子、或判据最硬的那一层）。
2. 针对它推 1–3 个节点，每个都写清推演链与反例。
3. 若两个节点互相冲突，就都保留（`kept`），把冲突写成待决问题 `Q-00N` 交给用户——**不要在推演阶段私自选一个**。
4. 用户拍板后，看输的那条要不要写进「淘汰的理由」：**淘汰必须写成有条件的判断**——"因为 <当时的推断/判据>，所以现在不选它"，并附一行**复活条件**（什么情况出现就该把它捡回来）。**推断变了，淘汰结论就作废**，回这一步重判。
5. 移到下一层。

门禁要求：**每个层至少挂一个节点**（`stage.S2.derivation`），所以不能只推喜欢的那一层。

## 一条推演依赖"程序怎么表现"时：三选一（当轮必做）

推演与淘汰太容易建立在一个**我没读过的事实**上（"它必然要用 niri"、"它不可能被暂停"）。这类句子一旦写成机制，就会拿去筛掉本来能用的候选。所以当轮必须选一条，并写进节点：

| 出口 | 什么时候走 | 落盘要求 |
|---|---|---|
| **① 读源码/文档/日志** | 盘上有源码或文档 | 写出**文件 + 行号或函数名**；写不出就是没读 |
| **② 承认没读** | 读了也没有定论 | 明写"我没读 X"，把它降级为反例或未验证假设（`evidence: E3`）；**不许再拿它当硬要求** |
| **③ 交给用户做实验** | ①②穷尽后仍必须真机实测 | 交接三件套（见下），并在 `tech/probes/` 记一条待验证 |

**判断标准是"读一次得到答案吗"**：能，就不许让用户重启机器。**禁止把 ① 该做的事推给 ③。**

### 交接三件套（缺一不可）

1. **交接文档** `tech/handoff-<主题>.md`：为什么必须实测 · 具体步骤 · **通过了算过 / 不通过该怎么办** · 回滚步骤 · 要收哪些日志；
2. **一段可直接复制的提示词**（写在交接文档里）：用户拿去在标准模式新会话里粘贴，自包含，**不读讨论对话也能执行**；
3. **回报格式**：结果写 `tech/probes/<id>-result-<日期>.md`，原始日志放 `tech/probes/evidence/`。

拿到结果后：先判断它**推翻了哪一条**（可能是机制命题、可能是判据），把结论落到对应文档，并在轮次纪要里记一笔。**实验是取证，不是实现**——不写生产代码。

## 清单要诚实：别把"我想到的"说成"只有这些"

给候选、给路径、给选项时（同一次推演里的"三条路"、`tech/options.md` 里的候选都算）必须写一行 **`清单来源:`**：

- 这份清单是从哪儿数的（本机现状 / 源码里的入口 / 某个包的仓库 / 推论）；
- **我查了哪些、没查哪些**，"因此可能漏掉什么"。

反模式：**假穷尽**——"这一屏由谁画只有三条路"。如果其中两条是排查出来的、一条是推出来的，那不是空间只有三条，而是**你只看了三个地方**。把这句话换成盘点，用户才有得比较。

## 什么时候该停下来回退

| 症状 | 说明 | 动作 |
|---|---|---|
| 某个层推不出任何自洽节点 | 这一层的判据可能自相矛盾，或者它不该在这一层 | 回 S1 拆层或合并层 |
| 推出来的节点必须引入新机制才能自洽 | 它其实是一个**新的理念候选**，不是这一层的推演 | 允许，但要挂到它真正的父层上，并在顶层（种子或根层）建一个节点承载它 |
| 两个层的节点互相要求对方 | 循环依赖 = 分层切错 | 回 S1 重新切 |
| 推着推着发现种子那句话本身站不住 | 种子错了 | 回 S0，把旧版挪进「被否的表述」 |

**推演失败是正当产出**：写进 `audit/verdict.md`（`V-00N`，结论"转向"或"终止"），明确告诉用户。硬造一个概念把树撑起来，比承认推不动更贵。

## 一个完整的推演例子

种子的 statement：*"让长时间读代码的人眼睛不累、注意力不被打断"*

- 层 `L-001 视觉层的"不累"`：判据 = 连续阅读 30 分钟后不出现视觉疲劳的自述
- 层 `L-002 认知层的"不被打断"`：判据 = 不被装饰性元素夺走注意（动效、强调色、边框）
- `N-001`（from `L-001`）：低对比度不等于不累 —— 长时间阅读需要**足够的字面对比 + 极少的色相对比**。反例：全灰配色在强光下反而更难读。调研佐证：E1（对比度标准 WCAG）+ E2（自测）
- `N-002`（from `L-002`）：装饰即干扰 —— 任何非承载信息的元素都在消耗注意力预算。反例：完全没有层级提示时，定位成本上升。
- `N-003`（from `N-001` + `N-002`，**合流节点**）：用纸与墨的关系组织界面：只有承载信息的墨色，没有装饰性的彩；层级靠字重与留白，不靠色块与阴影。
- `N-004`（from `L-002`，`status: dropped`）：暗色霓虹主题 —— 淘汰理由：色相对比高，与 `N-001` 的约束冲突；且装饰性强，违反 `N-002`。**复活条件**：若"不被打断"被重判为次要判据（例如用户改用短时高频查看而非长时阅读），它就不再与 `N-001` 冲突，应重新参加竞争。

顶芽是 `N-003` 收敛出的理念名（`纸墨`），而"低字面对比要够、装饰即干扰"这些**机制**落在侧枝的 `M-` 里，供选型阶段当限制条件用。注意 `N-004` 没有消失：它留在树上，是"为什么不是暗色主题"的答案。

## S2 出口条件（门禁）

- 每个 `L-` 层至少挂一个 `N-` 节点；
- 至少一个 `kept` 节点；
- 每个节点：`from` 非空且指向存在的 ID；`kept` 有反例；`dropped` 有淘汰理由；`evidence` 合法；
- **所有 `kept` 节点的祖先链都能走到种子**（无孤儿节点）；
- 依赖"程序怎么表现"的推演走过了三选一（读源码的写出处、没读的写明、要实测的进 `tech/probes/`）；
- 没有阻塞 S2 的未决问题。
