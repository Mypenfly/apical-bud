# 讨论协议（每轮怎么走）

## 这棵树

```
种子 seed/real-need.md  ──►  根系 layers/  ──►  主干 derivation/  ──►  顶芽 concept/concept.md
   （一句话真实需求）        （需求分层）         （理念推演节点）        （唯一的理念概念）
                                                                          │
                                                    侧枝 concept/extensions.md（M- 机制命题 / E- 概念延伸）
                                                                          │
                                                    果实 tech/selection.md（技术方案：判据挂在 M- 上）

调研 = 肥料：供给主干，不代替主干生长。      问答 = 生命力：树每长一节，都要经过一轮问答。
```

## 对话是介质，文件是留痕

这是本方法最容易被违反的一条，因为它反直觉：**文件越完整，讨论反而可能越糟**——如果用户必须打开文件才能参与，讨论就退化成了「它写、我读、我挑错」，问答的心流断掉。

| 渠道 | 承载什么 | 不承载什么 |
|---|---|---|
| 对话 | 提案原文、选项与代价、推演链、反例、异议、复述确认——**用户回答所必需的一切** | 长篇归档、完整表格 |
| 文件 | 已发生的事实：用户原话、已确认的层、已淘汰的节点、决策、轮次纪要、机械状态 | **未获答复的提案** |

四条硬规则：

1. **答复之前不落盘。** 拿到用户答复之后才写文件；本轮还没答复就先把提案写进文件，等于把讨论搬进了文件。
2. **提问自带内容。** 问题里出现 `L-001` 这类 ID 时，必须同时给出它的人话内容；只给编号 = 让用户去翻文件。
3. **自检句**：提问前问自己「用户如果从不打开任何文件，能不能回答这个问题？」不能 → 补齐对话内容再问。
4. **三种合法写文件时机**：① 拿到答复后留痕；② 用户明确要求出文档；③ 补机械记录（轮次纪要、state.json、用户原话）。

DSH preset 由写守卫兜底：本轮尚未拿到答复时，新建讨论文件会被拒绝并提示回到对话（用户原话、轮次纪要、state.json、audit/ 这些账本类文件不受限；用户明确要求记录、或用户在指出错误时自动放行）。

## 三条承重规则（不是修辞，门禁会查）

1. **没有父节点的不算概念。** 每个 `N-` 节点的 `from:` 必须指向存在的层或节点，且它往上必须能走到种子（`tree.connected` 检查）。凭空的灵感可以被讨论，但要先变成某个层的推演，才能进 `derivation/`。
2. **顶芽只有一个，机制可以有好几个。** 理念概念唯一；机制命题写在侧枝（`M-`），允许竞争、允许复活。淘汰的枝留在树上，不删。
3. **不确认不长。** 层没有用户确认（`confirmed: true`）就不许挂推演节点；术语没确认不许当既定概念用；反悔只认用户说过的话。

## 会话与树

一个项目会有多棵树（不同需求、不同阶段），所以**一个会话要绑定一棵树**：

- 开工先看：`apical_gate action=trees` —— 列出全部树、各自的阶段与生命周期（进行中 / 已到 S7 定稿 / 已终止）。
- 绑定：`apical_gate action=bind slug=<slug>`。项目里只有一棵树时自动推断；有多棵而未绑定时，工具与横幅会先要求绑定，而不是猜（猜错等于把两棵树混在一起讨论）。
- **已结束的树是历史记录**：在它上面继续追问细节没问题，但不要长出新的层与节点。新需求 → 新建一棵树，并在它的 `state.json` 里写 `dependsOn` 与 `relation`，在种子里写「## 与已有树的关系」（继承了什么、推翻了什么）。这是树与树之间唯一的追溯入口。
- 正文引用另一棵树的内容时写成 `<slug>#L-003`（例如 `paper-ink#L-002`）。
- 切换树用 `bind`：切换后写入范围与状态横幅都跟着变；守卫不允许一个会话同时往两棵树里写。

## 会话开始

1. 加载本 skill 与 `doc-conventions`。
2. 读 `design/` 下的 `state.json` 与 `README.md`。
   - 不存在 → 进入 S0：问清主题与 slug，建讨论根，照抄 `templates/state.json`。
   - 存在 → 复述当前阶段、层数、节点数、未决问题，然后开始本轮。
3. **每轮开始都重读 `state.json` 与最近一份 `rounds/round-*.md`**，不依赖对话记忆。上下文被压缩后，这是唯一可靠的恢复手段。

## 一轮的七个动作

```
① 读盘：state.json + README + 相关层/节点/问题
② 对话里重述：当前阶段 · 本轮要定什么 · 阻塞本阶段的未决问题有几个
③ 对话里给出完整提案：选项与代价、推演链、反例（用户不看文件也能判断）
④ 提问：ask_user_question，一个问题
⑤ 拿到答复 → 复述：1–2 句确认我记下了什么（含 ID）
⑥ 落盘（到这里才写文件）：层 / 推演节点 / 决策 → rounds/round-NNN.md → 术语表 → state.json（round++）
⑦ 收尾：门禁通过就 check → advance，否则报出下一个问题
```

**② 和 ③ 是同一条回复里的两件事**：先用一段话把提案说清楚，紧跟着提问。用户看到的应该是讨论，而不是「文件已更新」。

一轮只关闭一个问题，最多长一节（一个层或一个节点）。一轮长出两个以上的节点，说明问题切得太大——拆开。

**推进前多一步**：目标阶段是 S3 / S5 / S6 / S7 时，先做全量重判（见下），再 `check` → `advance`。

## 提问纪律

- **一次一问。** 一个 `ask_user_question` 只问一个问题；塞多个会摊薄注意力，也会拿到互相矛盾的答复。
- **选项数是结果，不是目标。** 1 个也行（说清为什么只有一个）、5 个也行（那就分两组）；**不要为了凑数造选项，也不要为了整齐砍掉一条真岔路**。一般 2–4 个。
- **每个选项写清得失**：内容、代价、**可逆性**（"选了还能不能改回来"）。选项的意义是让你**比对得失**，不是让你挑一个我推荐的。
- **写 `清单来源`**：这份选项是从哪儿数出来的、我查了哪些、没查哪些。**不写穷尽性的话**（"只有两条路"），除非真能证明。
- **"是 / 否"是最差的选项集**，除非问题真的是二元的。
- **能从文件、代码或调研查到的事实自己查**，不问用户。
- **只问用户拥有的东西**：目标、优先级、取舍、可接受的代价、价值判断、用词偏好。技术事实、可推导结论、文档格式不问。
- 提问前最多 3 句话铺垫，并说明"为什么现在问、不问会怎样"。
- **用用户的语言提问。** 不要用我刚造的词去问他；如果必须用一个新词，先请他确认这个词（见下）。

## 用户可以反悔（不是例外，是常规动作）

用户说"我反悔了 / 上一个决定撤回 / 我想改回某某"时：**不需要理由，不追问，当场承认，然后按下面的动作走**。

| 步骤 | 做什么 |
|---|---|
| 1 | 一句话复述撤回的是什么（含 ID 的人话内容），问一次"连带哪些也要收回"（只问一次，用户说不知道就由我列影响面） |
| 2 | 落盘：新建条目，frontmatter 写 `supersedes: <旧 ID>`；旧条目标 `superseded-by: <新 ID>`，**内容不动** |
| 3 | 结算波及面：受影响的层/机制命题/判据加 `stale: true`，在下一轮或下一次全量重判里逐条重判 |
| 4 | 轮次纪要写清：撤回了什么、为什么、波及到哪、下一步先做什么 |

**反悔的代价要如实说**（"这条一撤，S6 的三条判据要重写"），但**不阻止**。用户坚持时照办，并把我的顾虑写进 `audit/challenges.md`。

**不要偷偷改旧文档来"实现"反悔**——那是篡改讨论史；`seed/R-000-original.md` 与既有轮次纪要由写守卫兜底（append-only）。

## 全量重判（进 S3 / S5 / S6 / S7 之前）

每个阶段边界前做一次**全量重判**，结果写 `audit/recheck-<stage>.md`：

1. 列出全部待盘点项：`status: dropped` 的推演节点、被淘汰的竞争主张（概念层那些）、候选里的淘汰项、`## 未验证假设`、以及任何 `stale: true` 的文档；
2. 逐条写结论：**维持 / 复活**——**维持也要写一句为什么**（当时依据的哪条判据或推断，现在有没有变）；
3. 该复活的走反悔流程（`supersedes:` + `superseded-by:`），让它重新参加竞争；
4. 门禁会核对：待盘点项有没有漏；漏了就不许 `advance`。

重判不是走形式：`denial-greeter` 里有一条路在第 5 轮被判死、第 10 轮又被翻案采纳——那就是没有重判的代价。

## 用户可以改写

用户不满我的问法或我的用词时：

| 用户做了什么 | 我必须做什么 |
|---|---|
| 改写了一个问题 | 把原措辞移进 `questions/Q-00N` 的「用户改写」节，**以用户的措辞为准**重述影响面（哪些层/节点要跟着改） |
| 改了某个术语 | 全局替换文档与后续提问里的用词；在 `glossary.md` 的「曾用名」里记一行；在轮次纪要的「术语变动」里留痕 |
| 说"别再问这个了" | 把该问题关闭并在结论里写"用户判定此问题不影响任何层"，不要换个说法再问一遍 |
| 说"你给我的这堆词我看不懂" | 停下推演，逐个术语问"这个词你希望怎么叫"，改完之后再继续；不得边改边推 |
| 说"我反悔了" | 走上表「用户可以反悔」的四步 |

**术语纪律**：一轮最多引入 1 个新术语；新术语当轮写进 `glossary.md`，标 `[提案]`，等用户确认后才改 `[确认]`；`[提案]` 状态的术语同时最多 1 个（门禁阻塞项）。定义必须是人话，且不能用另一个还没定义的术语来解释它。

## 落盘顺序

**轮次纪要 → 层/节点/决策 → 术语表 → state.json**。反过来会出现"状态说已定而文档里什么都没有"——门禁会抓住，但那是自找的。

## 阶段推进与回退

- 出口条件由 `scripts/gate.mjs`（DSH 里是 `apical_gate` 工具）判定。**没通过门禁不许说"本阶段完成"。**
- `apical_gate action=check` 列出缺什么；`action=advance` 在缺件时直接拒绝。
- **回退是正常的**：S2 推不出自洽节点 → 回 S1 重新分层；S1 分层时发现种子那句话本身错了 → 回 S0。回退要写清原因与改了什么。
- S5 与 S7 两个定型点，默认建议做红队复核（见 `apical.md`）；用户可跳过，但跳过要记进轮次纪要。

## 语气与篇幅

- 反对要给证据与代价，不给形容词：说"这会导致 X"而不是"这感觉不太好"。
- 不奉承，不用复述用户的话来充篇幅。结论先写，理由后写。
- 不确定就说不确定，并说明"怎么才能确定"。

## 反模式清单

| 反模式 | 症状 | 正确做法 |
|---|---|---|
| 灵感冒充推演 | 节点没有父节点，或祖先链断在某个 `L-` 之外 | 回到它应该长出来的那一层重新推 |
| 调研代替推演 | "因为某项目这么做，所以我们的理念是…" | 调研只能提供前提与佐证；结论必须从层/节点推出来 |
| 没读过的能力当硬要求 | "它必然要和用户会话抢席位""它不可能被暂停"，但没读过它的源码 | 当轮走三选一：读源码写出处 / 承认没读并降级 / 交用户实验 |
| 假穷尽 | "只有三条路"，其实只看了三个地方 | 写 `清单来源` 与漏搜范围；盘点不是证明 |
| 分层即定论 | 只有一种分层方式，直接开分 | 每层至少保留一种"其他解读（被否）" |
| 一个目标吃掉其他目标 | 用户说了三件事，两件被降级成"约束"，之后再也不提 | 单独能问"做成什么样才算好"的，就是一个层 |
| 机制冒充理念 | 顶芽写成"挑现成的、可配置、能回退"，读起来是一份约束清单 | 概念回答气质与姿态，机制落到侧枝的 `M-` |
| 只淘汰不记复活条件 | 淘汰理由引用的是"当时的推断"，推断变了没人回头看 | 每条淘汰附复活条件；进 S3/S5/S6/S7 前全量重判 |
| 术语墙 | 文档里全是自造词，用户看不懂 | 一轮最多 1 个新术语、`[提案]` ≤1、定义用人话 |
| 过早收敛 | 第三轮就写出 `concept.md` | 先让主干长够：每个层都要有节点 |
| 概念多个 | "我们的核心是 A 和 B" | 必须选一个；另一个写成竞争概念或延伸 |
| 剪枝不留痕 | 淘汰的节点直接删掉 | 保留 `status: dropped` 与淘汰理由 |
| 用文档数量冒充进度 | 建了一堆空文件 | 进度 = 树的节数 + 未决问题归零 |
| 用文件代替回答 | 回复里只有「已写入 L-001，你看一下」 | 提案正文说在对话里，文件只是留痕 |
| 让用户读文件才能回答 | 问题里只出现编号，选项内容在文件里 | 提问自带内容，不打开文件也能答 |
| 答复前就落盘 | 先写文件，再问「这样对吗」 | 先问，拿到答复再写 |
| 沉默同意 | 有异议但没写进 `audit/challenges.md` | 每次异议都留痕，包括被驳回的 |
| 忘记读盘 | 靠记忆说"我们上次定了…" | 每轮先读 `state.json` 与最近轮次 |
