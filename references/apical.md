# S3–S5：理念概念、机制与侧枝

> **落盘时机**：本阶段谈定的任何内容，都先在对话里说清楚、拿到你的答复，再写进文件。**提案不落盘**——文件是留痕，不是介质。

目标：把主干上互相竞争的主张收敛成一个**能解释、能生成**的理念概念（顶芽），再把"靠什么保证它"写成机制命题与概念延伸（侧枝），然后定稿。

**两样东西不要混**：

| | 回答什么 | 判据 | 写在哪 |
|---|---|---|---|
| **理念概念** | 这一屏是什么气质、什么姿态 | 可解释（说得出它意味着/不意味着什么）+ 能生成（≥3 条具体主张） | `concept/concept.md`（唯一） |
| **机制命题 `M-`** | 靠什么保证它成立 | 可证伪 + 反例 + 边界 + 服务概念哪一句 | `concept/extensions.md`（可多个、可竞争） |

把机制写进顶芽，就会得到一个"条件 + 否定"的结论（能证伪的东西当不了理念名）；把理念写成一句可证伪的话，就会得到清单而不是概念。**两者各归其位**，收敛才收得动。

## S3：顶芽（理念概念）

### 收敛动作

1. 把 `kept` 节点并排（不是并排候选方案的参数，而是并排**主张**）。
2. 找出它们共同指向的那条**意向**——不是"必须怎么做"，而是"这样做的道理是什么"。
3. 写成：**「<名字>：<一句话，≤60 字>」**。名字用日常语言（纸墨 / 门厅 / 留白），一句话说清这个意向。
4. 自检两条：
   - **可解释**：说得出它意味着什么、不意味着什么（各 ≥2 条）；
   - **能生成**：至少能派生出 3 条具体主张（它们就是侧枝的种子）。**派不出 3 条，说明它还只是个形容词，回 S2 再推。**

正例：`纸墨：只有承载信息的墨色，层级靠字重与留白。` / `门厅：不是家的一部分，但一眼知道回到哪个家。`
反例：`一个智能的、可扩展的照片管理平台`（品类描述，既不解释也不生成）。

### 顶芽必须回答的事（门禁全部要求非空）

| 小节 | 内容 |
|---|---|
| `## 核心概念（一句话）` | 名字 + 一句话（≤60 字） |
| `## 这意味着什么` / `## 这不意味着什么` | 各 ≥2 条——防它滑成一句漂亮话 |
| `## 它生成的主张` | ≥3 条：由这个意向派生出来的具体主张（S4 的 `M-` 与 `E-` 从这里长） |
| `## 边界` | 管到哪里为止、什么时候不适用 |
| `## 非目标` | 与种子的非目标对齐，逐条列出 |
| `## 反例与失败边界` | 每个关键词取反，各找一个真实场景；**写不出反例等于没有边界** |
| `## 承接了哪些层的什么` | 逐条列出每个 `L-` 层由本概念的哪一句承接；被列入非目标的层也要出现 |
| `## 淘汰的竞争概念` | 表格：哪些概念没成为顶芽、为什么（门禁要求 ≥1 行） |

### 关键名词

概念名与一句话里的自造词，逐个写进 `## 关键名词`，每个都必须在 `glossary.md` 里已 `[确认]`。门禁核对：数量 1–3，且全部已确认。

**名字要能解释自己**：一个需要六个新词才能说清的概念，说明还没收敛，或词没选好。

### 顶芽写不出来时

这是**最常见的正当停滞**，三种处理：

| 症状 | 说明 | 动作 |
|---|---|---|
| 只能写成一个机制（"挑现成的、可配置"） | 你把机制当成了理念 | 回 S2：问"这样做是为了让人感觉到什么"，再往上收一层 |
| 只能写成抽象名词（"优雅""现代"） | 主干还没长够 | 回 S2，把那几个层再推一节 |
| 每个层各指向一个概念 | 可能有两个概念 | 让用户排序或砍掉一个；另一个写成竞争概念 |

连续 3 轮仍写不出一句话，就是该提出**项目裁决**的时刻：把"这个概念可能不成立"明说给用户，写 `audit/verdict.md`，而不是无限期讨论。

## S4：侧枝（机制命题 + 概念延伸）

`concept/extensions.md` 里两类条目**用 ID 区分**，都要带 `类型:` 行。

### `## M-00N <机制名>`（机制命题）

顶芽是意向，机制是**它的落地约束**——技术选型最终要照着 `M-` 走，所以它必须可证伪。

- `服务: 第 N 条 ← N-00N`：指向 `concept.md` 的「它生成的主张」里第 N 条，并写清它从哪个推演节点长出来（门禁校验两者都存在）；
- `## 机制`：主张什么、靠什么保证；
- `## 反例`：什么情况下它不成立；
- `## 边界`：它管到哪、不管什么；
- `档位: 必然 | 需求`（"需求"档还要 `来源: L-00N`/`N-00N`）。

机制命题**允许互相竞争**：两条冲突就都留着（`status: kept`），把冲突写成待决问题交给用户；也可以先搁置一条（`status: dropped` + 淘汰理由 + **复活条件**）。

**别把"我没读过的能力"写成机制**。要求某类实现具备某种能力之前，先读它的源码或承认没读（见 `derivation.md` 的三选一）——否则你会拿一条不存在的要求去筛候选，把本来能用的方案提前淘汰。

### `## E-00N <延伸名>`（概念延伸）

`档位:` 三档严格区分：

| 档位 | 含义 | 判据 |
|---|---|---|
| `必然` | 概念一旦成立就自动成立的东西 | 去掉它就得改概念 |
| `需求` | 为满足某个具体的层而加的扩展 | 必须写 `来源: L-00N`/`N-00N`（门禁校验该 ID 存在） |
| `猜测` | 可能是未来方向，没有任何层支撑 | 必须写"何时验证"的信号 |

**铁律：延伸不得引入新的运作原理。** 需要一套新机制的，不是延伸，是新候选 → 回 S2，让它作为节点参加推演与竞争。

同时写"明确不延伸的地方"：看起来顺理成章但被拒绝的方向，附理由。这一节未来最省时间。

## S5：定型（定稿 + 重判 + 红队）

### 定稿清单（门禁）

- `concept/concept.md` 的 `status: final`；
- **`## 推演链`**：`seed → L-00N → N-00N → ……` 的序列，**允许多条**（一层一行、或一个分支一行），每跳都对应节点自己的 `parent`/`from`；门禁逐跳核对，断链即拒绝定稿；
- **机制命题成文**：`extensions.md` 里每条 `M-` 都有 `服务:`、`## 机制`、`## 反例`；
- **全量重判已做**：`audit/recheck-S5.md` 逐条覆盖 dropped 节点 / 被淘汰的主张 / 未验证假设；
- `## 已知反对与回应` 非空：`audit/challenges.md` 里每条 `X-00N` 都逐条回应（采纳并改了哪里 / 驳回并给理由）；
- 所有决策不再是 `proposed`；
- 每个层在「承接了哪些层的什么」或非目标里有落点；
- 跑一次 `apical_gate action=check`。

### 红队复核（默认建议，用户可跳过）

自己给自己找茬的收益有限——**独立视角才行**。用 `subagent` 起一个只读子代理，提示词照抄（替换 `<>`）：

```
你是红队评审，任务是推翻一棵理念推演树，而不是称赞它。只读，不要修改任何文件。
读 design/<slug>/ 下的 seed/、layers/、derivation/、concept/concept.md、concept/extensions.md、audit/challenges.md。
产出 ≥3 条实质性反对，每条必须：
  1) 引用具体的层/节点/段落；
  2) 指出推演链上哪一跳是断的、或者哪个反例没被处理；
  3) 说明它会导致什么可观察的失败；
  4) 给出一个更简单的替代做法与可证伪判据。
另外专门检查三件事：概念是不是其实是个机制；有没有被淘汰的分支现在该复活；机制命题里有没有"没读过的能力"被当成硬要求。
不要提格式、措辞或文档组织方面的意见。宁少勿滥，但每条必须是真问题。
格式：## X-00N <标题> / - 主张 / - 证据 / - 代价 / - 替代方案 / - 可证伪判据
```

拿到结果后写进 `audit/challenges.md`，主会话逐条回应并写进 `concept.md`；若某条异议成立且需要改概念 → 回 S2/S3，并把回退记进轮次纪要。用户跳过红队要记进 `rounds/`。

### 未收敛也是正当产出

多轮之后仍无法用一句话说清、反例无法界定、或覆盖所有层需要两套冲突的机制 → 明确宣布未收敛，在 `audit/verdict.md` 写裁决（转向/终止/重启条件）并告诉用户。用模糊的漂亮话把讨论拖下去，是这一阶段最严重的失职。

## S3/S4/S5 出口条件（门禁摘录）

- S3：一句话 ≤60 字；关键名词 1–3 且全为已确认术语；这意味着/这不意味着/它生成的主张（≥3）/边界/非目标/反例与失败边界/淘汰的竞争概念 非空；每个层被承接或列入非目标。
- S4：≥3 条延伸；`M-` 条目有 `服务:`/`## 机制`/`## 反例`；`E-` 档位合法、需求档来源有效；术语表 ≥3 个术语。
- S5：`status: final`；推演链无断链（允许多条）；`audit/recheck-S5.md` 覆盖全部待盘点项；已知反对与回应非空；每条异议有结论；无 `proposed` 决策。
