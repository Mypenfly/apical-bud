# S3–S5：顶芽与侧枝

目标：把主干上互相竞争的节点收敛成**唯一一个核心理念**（顶芽），写出它的边界与延伸，然后定稿。

## S3：顶芽（收敛）

### 收敛动作

1. 把 `kept` 节点并排（不是并排候选方案的参数，而是并排**主张**）。
2. 找出它们共同指向的那条机制——它通常在**合流节点**上（父节点有多个的节点）。
3. 写成一句话：**「<机制>，使得 <谁> 只需要 <最小的动作/决定> 就能得到 <可观察结果>」**。
4. 检查：≤100 字；不含"和/以及/同时"式并列；能被证伪；不依赖任何具体技术；**关键名词 ≤5 个且全是你我确认过的词**。

正例：`用户只对删除做一次决定，其余分类与归档由可回退的自动规则完成。`
反例：`一个智能的、可扩展的照片管理平台`——品类描述，无法证伪，也不构成设计约束。

### 顶芽必须回答的四件事（门禁全部要求非空）

| 小节 | 内容 |
|---|---|
| `## 边界` | 管到哪里为止、由什么机制保证、什么情况下不适用 |
| `## 非目标` | 与种子的非目标对齐，逐条列出 |
| `## 反例与失败边界` | 把核心概念的每个关键词取反，各找一个真实场景；**写不出反例等于没有边界** |
| `## 分层覆盖` | 表格逐条列出每个 `L-` 层如何被覆盖；被列入非目标的层也要出现（门禁核对：每个层要么在这里，要么在非目标里） |
| `## 淘汰的竞争节点` | 表格：哪些 `kept` 节点没成为顶芽、为什么（门禁要求 ≥1 行） |

### 关键名词

一句话里出现的自造词，逐个写进 `## 关键名词`，每个都必须在 `glossary.md` 里已 `[确认]`。门禁会核对：数量 1–5，且全部已确认。

这条规则是防"术语墙"的第二道闸：**不能用一堆自造词去概括另一堆自造词**。如果一句话需要六个新词才能说清，说明还没收敛，或词没选好。

### 顶芽写不出来时

这是**最常见的正当停滞**，三种处理：

| 症状 | 说明 | 动作 |
|---|---|---|
| 必须用"和"才说得全 | 有两个顶芽 | 让用户排序或砍掉一个；另一个写成竞争节点或侧枝 |
| 必须引入第二套机制 | 两个层不兼容 | 回 S1 合并/重切层，或回 S0 检查种子 |
| 只能写成抽象名词 | 主干还没长够 | 回 S2，把那几个层再推一节 |

连续 3 轮仍写不出一句话，就是该提出**项目裁决**的时刻：把"这个理念可能不成立"明说给用户，写 `audit/verdict.md`，而不是无限期讨论。

## S4：侧枝（延伸）

`concept/extensions.md` 每条 `## E-00N` 必须带 `档位:`，三档严格区分：

| 档位 | 含义 | 判据 |
|---|---|---|
| `必然` | 顶芽一旦成立就自动成立的东西 | 去掉它就得改顶芽 |
| `需求` | 为满足某个具体的层而加的扩展 | 必须写 `来源: L-00N`/`N-00N`（门禁校验该 ID 存在） |
| `猜测` | 可能是未来方向，没有任何层支撑 | 必须写"何时验证"的信号 |

**铁律：侧枝不得引入新的运作原理。** 如果某条延伸需要一套新机制，它不是延伸，是新候选 → 回 S2，让它作为节点参加推演与竞争。

同时写"明确不延伸的地方"：看起来顺理成章但被拒绝的方向，附理由。这一节未来最省时间。

## S5：定型（定稿 + 红队）

### 定稿清单（门禁）

- `concept.md` 的 `status: final`；
- **`## 推演链`**：`seed → L-00N → N-00N → …` 的序列，每一跳都对应节点自己的 `parent`/`from`；门禁逐跳核对，断链即拒绝定稿。这是"新概念必须从前面推出来"的机器版本；
- `## 已知反对与回应` 非空：`audit/challenges.md` 里每条 `X-00N` 都逐条回应（采纳并改了哪里 / 驳回并给理由）；
- 所有决策不再是 `proposed`；
- 每个层在「分层覆盖」或非目标里有落点；
- 跑一次 `apical_gate action=check`。

### 红队复核（默认建议，用户可跳过）

自己给自己找茬的收益有限——**独立视角才行**。用 `subagent` 起一个只读子代理，提示词照抄（替换 `<>`）：

```
你是红队评审，任务是推翻一棵理念推演树，而不是称赞它。只读，不要修改任何文件。
读 design/<slug>/ 下的 seed/、layers/、derivation/、concept/concept.md、concept/extensions.md、audit/challenges.md。
产出 ≥3 条实质性反对，每条必须：
  1) 引用具体的层/节点/段落；
  2) 指出推演链上哪一跳是断的、或者哪个反例没被处理；
  3) 说明它会导致什么可观察的失败；
  4) 给出一个更简单的替代做法与可证伪判据。
不要提格式、措辞或文档组织方面的意见。宁少勿滥，但每条必须是真问题。
格式：## X-00N <标题> / - 主张 / - 证据 / - 代价 / - 替代方案 / - 可证伪判据
```

拿到结果后写进 `audit/challenges.md`，主会话逐条回应并写进 `concept.md`；若某条异议成立且需要改顶芽 → 回 S2/S3，并把回退记进轮次纪要。用户跳过红队要记进 `rounds/`。

### 未收敛也是正当产出

多轮之后仍无法用一句话说清、反例无法界定、或覆盖所有层需要两套冲突的机制 → 明确宣布未收敛，在 `audit/verdict.md` 写裁决（转向/终止/重启条件）并告诉用户。用模糊的漂亮话把讨论拖下去，是这一阶段最严重的失职。

## S3/S4/S5 出口条件（门禁摘录）

- S3：一句话 ≤100 字；关键名词 1–5 且全为已确认术语；边界/非目标/反例与失败边界/淘汰的竞争节点 非空；每个层被覆盖或列入非目标。
- S4：≥3 条延伸，档位合法，需求档来源有效；术语表 ≥3 个术语。
- S5：`status: final`；推演链无断链；已知反对与回应非空；每条异议有结论；无 `proposed` 决策。
