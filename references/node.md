# 一个推演节点怎么写

方法主干见 `SKILL.md`，一个完整正例与不该出现的形状见 [`writing.md`](writing.md)。这份文件只管**记录形状**：frontmatter、九个小节、以及一次一层与来路怎么标；可复制的骨架在 [`../templates/point.md`](../templates/point.md)。

## 一、一个节点 = 一条线索

一个节点 = 一条正在推的线索，通常就是一个问题、一个概念。文件名用"这一点在推演什么"的短句，两位序号开头：`03-该减少劣质还是增加优质.md`。序号即推演顺序，**最后一个节点就是现在的进度**。

## 二、frontmatter

```yaml
point: 03                    # 与文件名序号一致
title: 该减少劣质还是增加优质
status: open | closed | paused
what: 优质 / 劣质 token       # 这一步在谈哪个词（命名）
line: R-02                   # 服务哪条需求线（核心，或一条检验条件）
undecided: 0                 # 还剩几项没确定；收敛看它有没有涨
answers: [Q-02.1]            # 在回答哪一步生出的问题（可省）
from: [D-01.1, D-02.2]       # 拿哪些结论当前提（可省；只放 D-）
step: 命名                    # 五问里的哪一个（可省）
```

- `status`：`closed` = 结论已落定；`open` = 还在推；`paused` = 悬置，**写明什么事实能解开**。
- `what` 一个节点认一个词。想同时谈两件事，拆成两个节点。
- `undecided` 与 `## 未定项` 条目数对得上；这一版**收敛看它有没有涨**。
- `answers`／`from` 两个关系分开写，**两样都没有就是另起了一个话题**。第 1 个节点可省。

## 三、九个小节

| 小节 | 写什么 |
|---|---|
| `## 问题` | `Q-NN.1` 这一步在回答什么，用人话问 |
| `## 已知` | 逐条标来处：`[事实 F-002]` / `[结论 D-01.1]` / `[用户]` |
| `## 推论` | 因为…所以…；为什么必须是这几块；拿概念倒回去解释前面拆出来的东西；排除了什么 |
| `## 结论` | `D-NN.1` 一句话，可被反驳的命题（标 `type: 推论 \| 判断 \| 假设`） |
| `## 怎么落机制` | 谁读什么、什么时候读、拿到什么。指不出就写"还指不出，因为…"，**禁止留空** |
| `## 反过来` | 什么情况下这条结论不成立 |
| `## 生出的问题` | `Q-NN.2` 下一个问题 + 去向 |
| `## 未定项` | 没确定的事一条一行，每条注明什么事实或哪一步能解开。没有就写"无" |
| `## 用户` | 这一步里用户的原话与判断（没有就写"无"） |

五问落在哪：`what` 在 frontmatter；`parts`／`explain` 在推论；`how` 在「怎么落机制」；`new` 在「生出的问题」与「未定项」。分成 `## what` / `## parts` / `## explain` / `## how` / `## new` 五节写同样可以。

## 四、一次一层，来路指得出来

- **一次一层**：一个节点只答一个问题。想一次推完两件事，拆成两个节点。
- **问题与结论交替**是骨架；一个节点推进多次，并列多个 `## 结论 D-03.1 / D-03.2` 区块。
- **每个问题都要写「去向」**：`待答`／`悬置`／`由推演节点 NN 回答`。
- **`from:` 只放结论 `D-`，事实一律进 `## 已知`。** 出发点永远是上一步的结论。
- **`## 未定项` 是收敛判据**：收工时解决掉认领的，并说清有没有长出新的。
- **推不动就说推不动**：把"这条路走不通，因为…"写成结论，标 `closed`，这是正当结果。
- **实测与调研的产物进 `facts.md`**，节点里写"这条事实让哪条结论变成什么"。禁止把「我量到……」写成结论。
