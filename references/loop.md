# 推演的循环：拆词 → 论证 → 立概念 → 倒回去解释 → 生出下一个问题

一份需求进来（"低成本、高效果的 agent 系统"），推演这样往前走：

```
用户需求
 → 拆词            成本在哪、怎么算？效果受什么影响？
 → 逐项论证        成本＝命中输入＋未命中输入＋输出，前两者是总量的大头；
                   效果的影响项里，模型参数量不归本树管，内容质量与内容位置归
 → 得出一个抽象理念  信息密度
 → 拿它倒回去解释    优质 token / 劣质 token；compact 之后为什么糊涂
 → 从解释里得出下一个结论  引入副模型
 → 生出新问题        它要哪些信息、何时介入、怎么学、它自己的上下文多大
 → 回到「拆」……
 → 概念自洽且可实现 → 概念模型 → 实现选型 → 交接件
```

**每一步的内容都由前面已经写下的东西得出。最前面的东西是用户的需求。**

凭空来的东西——刚查到的事实、刚想到的说法——是材料，进 `facts.md` 与 `## 已知`；出发点永远是前面已经写下的那一句。

**两种"由前面得出"要分开写**，混在一起就分不清这一步在答哪条线、由哪一步长出来：

| | 写在哪 | 意思 |
|---|---|---|
| `answers: [Q-03.2]` | 回答问题 | 这一步在回答**哪一步生出的问题** |
| `from: [D-03.1]` | 拿结论当前提 | 这一步由**哪些结论**长出来（只放 `D-`，不放 `F-`） |
| `line: R-02` | 认领需求线 | 这一步服务**哪条需求线** |

`line:` 是服务关系，`answers:`／`from:` 是来路关系。一条线可以有很多步（`line:` 相同），但每一步的来路必须指得出来。

**一个点只标一个循环位置**（`step:`）。想同时拆词又论证，就拆成两个点——一个点做两件事，读的人分不清这一步到底推进了什么。

---

## 六个动作

### 一、拆词：拆的是需求自己的词

需求是一句愿望。第一步是**把它自己的词逐个拆开**，不另起名目：

- **名词**问：由什么组成？怎么算？
- **形容词**问：有哪些特征？具体怎么评价？

| 需求 | 拆出来的项 |
|---|---|
| 低成本、高效果的 agent 系统 | 成本在哪、怎么算？／效果（性能）受什么影响？ |
| 现代的、美观的 agent 前端界面 | 必要功能有哪些？／"现代的"有哪些特征？／"美观"怎么评价？ |

**每一项写成一条线（`R-01`…），问的是一个客观问题**：有外部答案，不取决于谁的感受。「成本由哪几项组成」可以；「你现在哪里不满意」不行。

**需求线只放需求里的词。** 推演中冒出来的问题进推演点的「生出的问题」——那条线是这棵树的产物，不是需求的构成项。

**形容词必须被拆到能判为止。** "美观"拆不出"怎么评价"，这一项就永远推不动，后面所有关于它的结论都是形容词串。

### 二、论证：一项一项回答掉，调研在这里

拆出来的每一项都要**有依据地**回答，答案来自外部事实：官方文档、源码、论文、账单、实测输出。这一步会得出两样东西：

1. **材料**：这一项到底由哪几块组成，哪几块是大头。
   - 成本＝缓存命中输入＋未命中输入＋输出，前两者是总量的大头。
   - 效果的影响项：上下文内容质量、内容在上下文里的位置（开头与结尾权重最高，与注意力机制有关）。
2. **范围**：哪一项不归本树管，在这里排除掉，并说清为什么。
   - 模型参数量（"模型多大"）不归 agent 系统开发管——它是选型输入，不是本树能动的量。

**排除是这一步最重要的产物之一。** 不排除，后面每一步都会拖着不属于这棵树的东西走。

**论证要到子项一级。** 一条线里常常含着好几项（"坐标：维度、原点、度量"），每一项都要点名回答掉；答不了的标「（待答）」。整条线答一半就过去，后面每一步都建在没答的那半上——而且没人看得出来。

### 三、立：从这些答案里得出一个抽象理念

把几项论证合到一起看，得出一个能同时罩住它们的词。它必须**能算**或者至少**能判**，否则它只是好听。

- "成本和效果在 agent 领域里一体两面" → **上下文中的有效信息密度**。
- 定义落地：密度 = 起引导作用的 token ÷ 全部 token。

**这一步的产物是一个概念，不是结论表。** 一个概念顶得上一串"因为…所以…"。

### 四、倒回去解释：拿这个概念解释需求与刚才拆出来的每一项

新概念要能解释你已经拆出来、论证过的东西，解释不通就换词。这是循环里最容易跳过的一步，也是唯一能当场验证概念的一步。

- 用密度解释现象：传统 harness 是"纯增长 + 用户自行 compact"；compact 之后优质 token 的**比例**上升、**总量**下降——所以模型在 compact 之后有一段糊涂。
- 再把论证过的成本三项重挂一遍：它们逐条对应到"劣质 token 占计价 / 劣质 token 干扰输出并继续变成劣质 token / 每次重开 session 重新取样"。

**解释不通的地方就是问题所在地**，它生出下一步。

### 五、长：从解释里得出下一个结论，再问出新问题

推演不停在"解释得通"。解释的过程中会浮出一个新结论，新结论又逼出新问题。

- 从"劣质 token 识别不了、优质 token 认得出来"这个**不对称**，得出：提高效果的方向是**注入**——过滤这条路的门槛是先认出劣质 token，而这一步谁也做不到。
- 顺着问：谁来判断、判断什么、什么时候判断 → 于是**引入副模型**，接过人在"修正 / 引导"里的角色，用户回到需求与创新的位置。
- 再问：它要哪些信息？何时介入？介入多深？它自己的上下文怎么管？主副都满时怎么办？
- 推一条子问题撞上新矛盾（它要的信息比主模型还多）→ 试探解法（按信息模块拆）→ 又生两个新问题（怎么切、并发与成本怎么平衡）。
- 把此前假定不会发生的因素提出来（信息时效性）→ 推出后果：优质 token 会劣化，而它一旦劣化，依赖它的一切跟着变劣质。

**每个结论都要能生出问题。** 生不出问题的概念，要么已经自洽（可以收敛），要么是死路（写出来，标 `closed`）。

### 六、收敛：概念自洽且可实现

- **自洽**：每个组成部分都能被同一套说法解释。
- **可实现**：能指到具体机制或接口——谁读什么、什么时候读、拿到什么。
- 两样都到了，写进 `model.md`（顶芽）；还没到，写进「还没确定什么」，每条注明什么事实能解开。

## 三个偏离的形状

### 一、拆出来的不是需求自己的词

**症状**：需求里明明写着"现代的、美观的"，推演链上四条线却换成了自造的名目（控制线、可读线、干预线、信任线），"美观"只在最后被抽象成一句"状态密度与注意力预算的匹配"。

**怎么发生的**：循环第一步写成了"拆成客观问题"，没写"拆的是需求自己的词"——于是模型自己发明了四条听起来更专业的线，用户的词被换掉了。

**防法**：拆词列成表，左边一列就是需求里的词；形容词必须拆到"怎么评价"为止。需求线里出现需求中没有的名目，就是拆错了。

### 二、一条需求线吃掉整棵树

**症状**：核心问题写成一句查账问题（"哪部分钱是白花的"），另一条需求线在全部推演点里出现 0 次；11 个点全在成本侧，效果侧等用户自己写出来。

**怎么发生的**：写种子之前先做了一轮成本调研，核心问题是在调研之后写的——轨道在这里就铺歪了，后面每一步都合规。

**防法**：种子先立（一句话需求、需求线、核心问题），再出去调研；核心问题必须同时压住每一条线，压不住就在种子里明写哪条降级、为什么。

### 三、最近调研到的东西当了推演的引子

**症状**：每个点的 `from` 里躺着这一步刚测出来的那条事实，`from` 里的结论只是装饰；结论跟着测量跑，测量又生出下一个"要测一个数"的问题。12 个点里好几个的问题本身就是测量题（命中率多少、模型会不会回去取），最后变成"用户说一条经验 → 我去量 → 报告我量到了什么"。

**怎么发生的**：纪律里写了"想谈现有系统就把它当外部事实去查"，于是"查"被当成了推演的内容。

**防法**：每一步的内容都由前面已经写下的东西得出——论证里查到的事实进 `facts.md` 与 `## 已知`，推演点里写"这条事实让哪条结论变成什么"。**一个点里得出的是概念或判断，"我量到 X"是一份材料。**
