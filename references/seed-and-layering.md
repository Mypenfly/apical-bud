# S0–S1：种子与根系

> **落盘时机**：本阶段谈定的任何内容，都先在对话里说清楚、拿到你的答复，再写进文件。**提案不落盘**——文件是留痕，不是介质。

目标：把一句可能模糊的话，变成**一句话真实需求（种子）**，再把它分解成**若干可推演的层**。

这一阶段最贵的错误不是理解错了，而是**用我的措辞替换了你的需求**：分层本身是一种解读，只写一种分法，就等于我替你决定了这件事该怎么看。

## S0：种子（需求对齐）

### 两步

1. **原话落盘**：`seed/R-000-original.md` 逐字记录用户的原始陈述，不润色、不总结、不纠正用词。模糊和矛盾是原始材料的一部分，不是要修掉的瑕疵。
2. **对齐一句话**：把 `seed/real-need.md` 的 `statement` 写成一句话（≤80 字），然后问用户确认。

### 如果用户一开口就是模糊的

不要追问十个维度。先问那一个能把话变短的问题：

> **"这东西做成之后，哪一件现在做不到的事变得能做到？"**

拿到回答后，把它压成一句话给用户复核。压不短通常意味着三种情况之一：

| 症状 | 说明 | 处理 |
|---|---|---|
| 必须用"和"才能说全 | 其实是两个需求 | 问哪个先做、哪个是另一个的前提；把另一个写进非目标或另开一层 |
| 只能写成抽象名词（"一个智能平台"） | 用户还没想清楚，或这个词是别人的说法 | 追问"如果我说它不是 X，你会怎么反驳我"，逼出可检验的表述 |
| 一句话是矛盾的（"全自动又每一步可控"） | 两个诉求在冲突 | 立刻提出异议，写 `audit/challenges.md`，让用户排序 |

### statement 的判据

- ≤80 字，且**用用户自己的词**（不是我的术语）。
- 能被检验：说出"什么发生说明它成立了""什么发生说明它不成立"。
- 允许是**当前对齐版本**，不是终稿。以后被推翻时，把旧版移进「被否的表述」，而不是直接改写历史。
- 一句话不是方案："做一个纸墨风格的前端"是方案；"让长时间读代码的人眼睛不累、注意力不被打断"才可能是需求。

### 必写项

- `## 被否的表述` ≥1 条：曾经写过/说过的版本 + 为什么否。**没有它就无法证明对齐发生过**（门禁检查）。
- `## 非目标` ≥1 条：不做什么、不服务谁。没有非目标的需求等于没有边界。
- `## 判定对齐的信号`：**多条、成对**——每条写"什么情况说明它成立了"和"什么情况说明它不成立"。这一节是 S1 的输入：**需求收敛时被挤掉的目标，就靠它找回来**。
- `status: confirmed`：用户确认那一句之后才改。

## S1：根系（需求分层）

### 分层的方法

从表层（字面意思）往下问"这句话到底在说些什么"，每一层都要能被父层的判据需要：

1. **先把种子里被压缩掉的信号摊开**：一句话的需求通常背着 2–4 个目标（"看得舒服 + 改得动 + 还能登进去"）。**它们没有主次之分之前，不许先定主次**——排序是用户的事，而且排序不等于丢掉。
2. **列出表层可能的解读**（至少两种）。例：需求是"设计一个看着舒服的前端"，至少有两种解读：
   - **视觉层**：什么样的视觉让眼睛舒服（对比度、留白、字重、动效克制）；
   - **认知层**：什么样的信息组织让脑子不吃力（层级、密度、可预期性）；
   - 还可能有第三种：**情绪层**：什么让它显得可信、不聒噪（材质、色彩、留白节奏）。
3. **让用户选一种**（或组合，但组合也要按层拆开写）。选中的写成 `layers/L-00N`，被否的解读写进这一层的「其他解读（被否）」——**门禁要求每层至少保留一条**。
4. **每层认领信号**：每条信号由某个层承接，或明写进种子/本层的非目标。**一条信号不能既没人认领、又没人拒绝**。
5. **判断这一层能不能再分**：如果它的判据还需要靠两个互不相干的东西来满足，就再分一层；否则停止。**分层的下限是"能挂推演"，上限是"仍能被一句话说清"。**

### 别把一个目标压成"约束"

最常见、也最贵的偏差：用户说了三件事，回答时选一件当"层"，另外两件降级成**约束**（"不因它而牺牲即可"）。约束在后面的讨论里不会被单独展开，于是那两件事到 S7 都没被真正考虑过。

判据很硬：**如果一件事单独拿出来也能问"做成什么样才算好"，它就是一个层**，哪怕它在排序上靠后。约束只能承载**属性**（"不能更慢"），不能承载**目标**（"要好看到什么程度"）。

### 层文件的必写项（门禁检查）

| 字段/小节 | 含义 |
|---|---|
| `parent: seed` 或 `parent: L-00N` | 这一层从哪长出来；父节点必须存在 |
| `## 分解理由` | 父层的哪条判据必须靠这一层回答（证明是忠实分解，不是另起话题） |
| `## 其他解读（被否）` ≥1 条 | 被否掉的那种分层方式与理由 |
| `## 判据` ≥1 条 | 这一层怎么算想清楚了，可观察 |
| `## 承接的信号` ≥1 条 | 本层承接种子「判定对齐的信号」里的哪一条（或被明写为非目标） |
| `confirmed: true` + `status: confirmed` | 用户确认过 |
| 祖先链通到种子 | 门禁会沿 `parent` 一路走到 `seed` |

### 模糊词处理

任何无法检验的词（"智能""一体化""高性能""易用""实时"）必须当轮操作化：写进 `glossary.md`，格式 `- **词** [提案]：一句人话定义`，请用户确认后改 `[确认]`；或者干脆换成用户能检验的说法。用户也可以直接改掉这个词——改了就全局替换并记曾用名。

追问句式：**"如果我说它是 X，你会用什么事实反驳我？"** 答得出来就有定义，答不出来就换表述。

### 层与术语的分工

- **层**回答"这个需求在问什么"（结构）。
- **术语**回答"这个词在这个项目里指什么"（语言）。
- 不要用术语代替层，也不要用层代替术语。一个词如果只有我有定义，它就是 `[提案]` 术语，先问用户。

## S0 出口条件

- `seed/R-000-original.md` 非空（≥20 字）；
- `seed/real-need.md`：`statement` ≤80 字、`status: confirmed`、「被否的表述」≥1、「非目标」≥1；
- 没有阻塞 S0 的未决问题。

## S1 出口条件

- ≥2 个 `L-` 层，每层满足上面表格里的全部必写项；
- 每层的祖先链通到种子；
- **信号追踪齐全**：种子「判定对齐的信号」里每一条，都由某个层承接或明写为非目标；
- 没有阻塞 S1 的未决问题；
- 术语表可用：每个术语有 `[确认]`/`[提案]` 标记与一句人话定义，`[提案]` 不超过 1 个。
