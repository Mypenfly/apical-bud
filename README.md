# apical-bud（顶芽）

**从用户第一个动作起，把程序的数据流推出来；先查已有项目，再按动作链切最小片实现。**

[English](README.en.md) | 中文

它只规定三件事：数据流怎么推、已有项目怎么比、实现怎么切。没有阶段，没有门禁，没有体检器。

两条不变量：**核心是主动作链，恰好一条**；**缺口必须被解决，且不再增长**。

## v2 改了什么

七件，方向都是减法：

- **推演从概念树改成用户第一视角的数据流图**。图的根是用户启动程序；每条需求线从某场景下用户的一个具体动作开始；系统自己触发的东西必须能沿某条用户动作链到达，图上不留孤儿。
- **任何「要自己写」的结论之前先查已有**。顺序：同生态插件市场（0 迁移）→ 同类开源 → 官方社区。硬环节覆盖够、迁移痛点可接受，两条都过才迁移；先让用户跑一次最短路径再判痛点；任一条不过就自研，记一行哪条不过。
- **实现成为推演的终点**。按用户动作顺序切最小片：切片 0 是有槽的骨架，之后每片端到端填一个动作，跑得起来、看得见、明确不做别的。
- **精简降为次一级约束**。L1 到 L3 都满足后取工程量最小；抽象有第二个使用者才建，当前动作链不需要的配置一个不加，能用依赖解决的不自己写。
- **边界提成必填三问**：不做什么、做不到什么、只适配什么场景，每条带越界后果。
- **文件从九个减到两个必写锚**：`seed.md` 与 `flow.md`，其余按需。记录只在四种时刻发生：结论被认下、边界变了、选型定了、切片完成。
- **体检器删了**。66 KB 检查脚本与 47 KB 自检一起删；硬项只剩四条（主链恰一条、flow 有一条完整路径、边界三问填齐、现状是新的），肉眼可验。

## 指令优先级

六层，从高到低。冲突时高的覆盖低的，不并排折中；同一层内冲突，回来问用户。

| 层 | 管什么 |
|---|---|
| L0 不可交易 | 诚实、不越权、不越过边界 |
| L1 范围 | 用户第一数据流、场景卡与压力卡、边界三问 |
| L2 达成 | 动作链闭环，用户每一步看得见，失败有出口 |
| L3 手段 | 先查已有；两条都过才迁移，否则自研 |
| L4 精简 | 次一级约束：上面都满足后取工程量最小 |
| L5 记录与说话 | 只记必要的、一到五句 |

## 一轮怎么走

1. 读 `flow.md` 的「现状」，挑一个动作。
2. 把动作画进图：状态、边、读什么写什么、失败从哪退。
3. 找出这一格的缺口，逐个解决；解决不了标「不可解＋解锁条件」。
4. 要自己写的东西，先查已有。
5. 缺口清零、主链闭环，进实现。

**图上四问**，每条动作边走一遍：谁在什么状态下做什么／读到哪些数据、写到哪些数据／用户看到什么／失败时看到什么、从哪退出。四问走完，动作要么成立，要么变成缺口。

**收敛三条**：主链闭环（每个状态有写者、每条动作有出口、每个可见结果有来源）、缺口清零或每条标不可解、没有新概念。三条都到才算推完。

## 实现

推演的终点是按动作链切的最小实现，顺序就是用户动作的顺序。

- **切片 0**：每个主链动作一个可见入口，点下去可以什么都不发生。
- **切片 n**：端到端填一个动作，跑得起来、用户看得见、明确不做别的。
- **禁止**：先建抽象层或配置系统再填动作；引入当前切片不需要的依赖。

**会话按工程量选**：

| 推演会话里直接做 | 换标准模式会话 |
|---|---|
| 切片 ≤2；单文件或小目录；零新增依赖；一次写完能看见；不用装环境 | 要装依赖或改构建；要反复调试；要迁数据或接外部；切片 ≥3；要动现有实现 |

同会话实现时，DSH 的写守卫默认仍拦 `design/` 之外：在宿主设 `DSH_APICAL_UNLOCK=1`，或在 preset 的 `allowPaths` 里放行项目目录。

## 旧树

v1 的九文件讨论根（`seed.md` + `facts.md` + `derivation/` + `model.md` + …）原样保留、只读、不检查、不迁移。要接着做，就在同一项目里按 v2 新开一个讨论根，并在新 `seed.md` 里写一句「与已有树的关系」：继承了什么、推翻了什么。

## 与上一版的关系

**v1** 是一台阶段机：S0–S7、每阶段出口条件、轮次纪要、全量重判。实测暴露了它的代价——机械的条例增长、过早收敛、门禁反过来牵着推演走、用词公文化。

**v1.5** 撤掉了阶段机，只留「文件组织＋用语」，进度交回给文件与编号。它的漏洞是收不了尾：未定项只增不减，节点可以一路长下去。

**v2** 换掉推演的根：不从抽象概念出发，从用户第一个动作与数据流出发；在写下任何「要自己写」之前先查已有；把实现收进方法本体，按动作链切最小片；用精简与边界防过度设计；删掉体检器与大部分文件要求。省下来的注意力放在图上。

## 出处与许可

提问纪律（一次一问、能从文件查到的不问人）取自 [grill-me](https://github.com/RobMitt/grill-me-skill) 的思路；把它最有害的一条——「每个问题都写出我的倾向」——去掉了：给了「选项 + 我的倾向」，讨论就变成「我给现成方案、用户盖章」。现在的形态是把张力摊开、把用户的理由要出来。
