# apical-bud（顶芽）

[English](README.en.md) | 中文

**把一句需求推演成抽象概念模型的记录规范。** 它只规定两件事：**文件怎么组织、词怎么用**——不规定每轮必须产出什么，也没有阶段、门禁与轮次纪要。文件是推演与论证的记录。

它另加两条不变量，它们决定这棵树有没有在干活：**核心只有一个**、**未定项必须被解决且不再增长**。

```
seed.md ──► facts.md ──► derivation/ ──► model.md ──► build/ ──► handoff.md
 种子         事实与调研   推演节点        顶芽        技术选型     果实
 一个核心                  节点循环：      (概念自洽    判据／方案   交接件
 检验条件                  命名→组成→为什么  且可实现)   ／实验／选型  + 能跑的实验
 放弃代价                  →怎么落机制→新概念                文件与数据
 核心问题                        └── map.md（进度、下一步、需求线覆盖、概念链、未定项；工具生成）──┘
```

## 它要解决什么

一次讨论最容易变成两种东西：**给现成方案**，或者**给流程交作业**。前者是"跳过推演直接谈理念"，后者是"按阶段生产文档"。这一版把两头都堵住，并且把**浪费**提前到推演阶段来定价：

- **先让用户只留一个核心**：用户一口气要的从来不止一样。「低成本、高效果」买不全。把原话里要的每一件摆出来，选**恰好一个**核心，其余降为**检验条件**（核心达成时不许破的底线，超过 3 条就提醒"要的太多"）或**非目标**，并写下**放弃代价**：放弃了哪条、会失去什么、我可能错在哪。
- **推演是一棵节点树**：一个节点在循环里走一遍——**命名 → 组成 → 为什么 → 怎么落机制 → 生出新概念／新问题**。节点数不设上限，五问只是一种展开方式；关键是别跳过任何一问，最常被跳过的是「怎么落机制」。
- **收敛的判据是硬的**：这个新节点有没有产生新的理念上的问题。每个节点写 `undecided:` 与 `## 未定项`；**未定项只增不减就是没在收敛**，是铺摊子。
- **实验可以推翻理念**：到了技术选型，允许也建议用实验去撞它——实验可以推翻 `model.md`，也可以得出"这个需求本身不可行"。**这一层只产出实验文件**，用户换一个标准模式会话去跑、把结果带回来。没写杀判据的不算实验，算演示。
- **果实是两样东西**：`handoff.md`（自包含、含**验证状态**：哪条已证实／已被推翻／还没验）**加** `probe/` 下能跑的实验文件与数据。
- **进度写在文件与编号里**：推演节点一点一文件、按序编号，点内编号是 `Q-03.1`／`D-03.1`——**编号自带进度坐标**；`map.md` 里还有**需求线覆盖表**（哪条线推到哪、哪条一个节点都没有）、**概念链**、**未定项**与一句「**下一步**」，新开一个会话只读它就接上。
- **记录不会过时**：一条结论被认下就**当轮写回文件**——用户原话进 `seed.md`（只追加）、结论进节点、未定项的增与减在 frontmatter 与「## 未定项」**两处同时改**、新术语进 `glossary.md`，最后刷新 `map.md`。**新会话或上下文被压缩之后**，先读 `map.md` → 最后一个推演节点 → `model.md`，再**用三句话复述"停在哪、上一轮定了什么、下一步谈什么"**，等用户纠正之后再往下推。**记录跟不上对话，是这棵树最快丢进度的方式。**
- **用语被当作规范的一部分**：写"因为／所以／如果／反过来／代价是"，不写"阶段／门禁／出口条件／落盘／轮次／完成"。
- **提问是把张力摊开**：形态是"这两条不能同时成立，你放弃哪一条、为什么"，外加"我押哪条、我可能错在哪"。
- **默认读者不是本行技术人**（`seed.md` 的 `reader:` 可覆盖）：技术词可以出现，但第一次出现要当场落地——它是什么、拿什么例子认得出、在别处指什么而这里指什么。**公式里的每个量都要讲完**（指什么／从哪观测到／单位或量级／怎么数；给不出"怎么数"的标「候选（待答）」）。**从常用词借来的词要声明差在哪**——`成本`、`密度`、`命中`、`优质` 这类词，用户以为是你说的那个意思，其实是你定的那个意思，同名不同义就是误解的来源。**降低门槛靠解释，不靠模糊**；判据一句：用户不懂时会不会不得不问第二次。
- **概念要能走一遍**：概念第一次成形时，节点里加一节「## 走一遍」——拿一条具体输入，从进入到结束走完全程。「怎么落机制」是机制视角（谁读什么），这一节是时间视角；只写前者，用户会以为自己懂了，直到实现时才发现每一步都对不上。

## 一次推演怎么走

| 文件 | 装什么 |
|---|---|
| `seed.md` | 用户原话（只追加）、一句话需求、**需求线（拆词，含角色：核心／检验条件／非目标）**、**核心与放弃代价**、**核心问题**、非目标、什么叫成了、被否的表述、`needs_probe`、可省的 `reader:` |
| `facts.md` | `## F-001` 事实 + 出处 + 等级（E1 文档源码／E2 实测／E3 二手）+ 用途；末尾一节「没查的」 |
| `derivation/NN-<词>.md` | 一个推演节点：问题／已知／推论／结论／**怎么落机制**／反过来／生出的问题／**未定项**（＋概念成形时可选的一节**走一遍**） |
| `model.md` | 抽象概念模型（顶芽）：名字、一句话、组成、接缝与边界、确定了什么／还没确定什么／反转：什么情况下这棵树不成立 |
| `build/01-判据.md`、`02-方案.md`、`04-选型.md` | 判据先写、方案后看，选型定稿；淘汰者写拒绝理由与复活条件；`03-实验.md` 只在需要实验时写 |
| `probe/` | 实验件：能直接跑的脚本 + `README.md`（跑法、回答哪个 `Q-`、**杀判据**、结果记录处） |
| `handoff.md` | 果实之一：自包含，可直接转交标准模式实现（含验收、第一件事、可复制的提示词、**验证状态**） |
| `map.md` | 进度、**下一步**、需求线覆盖表、概念链、未定项——**工具生成，模型不手写** |
| `glossary.md` | 术语：`- **词**：一句人话定义`（从常用词借来的要写「别处指什么／这里指什么／差在哪」；附「曾用名」「不用的词」） |

一个推演节点长这样（摘要，完整写法见 [`references/writing.md`](references/writing.md)）：

```markdown
---
point: 02
title: 该减少劣质还是增加优质
status: open
what: 优质 / 劣质 token   # 一个节点认一个词
line: R-02                # 服务哪条需求线
undecided: 1              # 还剩几项没确定——收敛看它有没有涨
answers: [Q-01.2]         # 在回答哪一步生出的问题
from: [D-01.1]            # 拿哪些结论当前提（只放 D-）
---
## 问题    Q-02.1 提高上下文密度，该从减少劣质片段入手，还是从增加优质片段入手？
## 已知    [事实 F-002] 能一眼认出的劣质特征只有浅层那几类；需要上下文才能判断的，人和模型都认不出。
## 推论    减少劣质要求先认出它，而"认出"本身更难；增加优质只需要在事情变坏时给出基于事实的判断。
## 结论    D-02.1 只做"增加优质"这一侧。放弃"清理已有上下文"。
## 怎么落机制  只读异常点附近的片段；在错误将要固化时注入；注入内容必须带出处。谁来判断还指不出来。
## 反过来  若注入总是晚于错误的固化，这条不成立。
## 生出的问题  Q-02.2 谁来判断"将要固化"？（去向：由推演节点 03 回答）
## 未定项  触发者与时机没定；由推演节点 03 回答。
```

**一个节点走一遍五问**：`what` 命名落在 `what:`，`parts` 组成与 `explain` 为什么落在「已知／推论」，`how` 落在「怎么落机制」（指不出就写"还指不出，因为…"），`new` 落在「生出的问题」与「未定项」。分成 `## what` / `## parts` / `## explain` / `## how` / `## new` 五节写同样可以。**概念第一次成形时再加一节 `## 走一遍`**（可选）：拿一条具体输入从进入到结束走完全程——机制写得再细，读者也是靠这一节才拼出整幅画面。

**用户已经给了结论怎么办**：把它登记成"待推导的结论"，从需求正推一遍——推得到，它才被论证；推不到，它就是假设或竞争概念，并说清差在哪一跳。不许拿它当前提直接用。

## 实验与果实

理念推得自洽只说明它**说得通**，不说明它**成立**。技术选型这一步允许用实验去撞它：

- **要不要实验在种子里就定**（`needs_probe: yes | no`）。有几棵树本来就不需要（纯选择性问题、纯外部信息问题）——**按需选择，不设实验是合法选择**，但要在 `build/04-选型.md` 里写一句为什么。
- **讨论会话不跑实验**：它只产出实验件到 `probe/`，用户换一个标准模式会话去跑——那边能直接改代码、连着迭代，而讨论会话的长上下文跑实验又慢又不准。
- **没写杀判据的不算实验，算演示**：跑之前先写死"什么结果会杀死这个理念"。结果回来记进 `facts.md`（E2 实测），节点里写"它让哪条结论变成什么"。**推翻了就写推翻**——一次成功的证伪比十个确认值钱。
- **需求被证伪也是合法结局**：写进 `handoff.md` 的「明确不做」与 `model.md` 的「反转」。省下的实现成本就是它的成果。

## 体检（很轻）

只查**组成成分与非空**：种子各节在不在（含**需求线**，且**核心恰好一条**）、事实与术语表在不在、有没有推演节点、节点的「问题」「结论」空不空、模型与选型文件若存在是否成形、`probe/` 下的实验件有没有要回答的问题与杀判据。**其余一律只是警告**：

- 推演有没有偏：某条需求线一个节点都没有、连着四个节点都在同一条线上、连着几个节点没有出现新概念、**写进种子的检验条件没有任何节点在验它**；
- 账有没有算：**检验条件超过 3 条**（提醒"要的太多"，不拦）、种子里没有「核心与放弃代价」；
- **收敛有没有发生**：连着几个节点的**未定项只增不减**；
- 锚有没有挂错：`from:` 里放了事实、节点没写 `line:`／`what:`、编号指向不存在、第 2 个节点与上一步无关；
- **记录有没有跟上对话**：`undecided:` 与「## 未定项」条数对不上（**两处只改一处，`map.md` 里那个进度数字就是错的**）、`map.md` 里「现在停在／下一步」两行与文件现在写着的对不上（**内容级比对——`mtime` 会被 checkout、复制、编辑器保存重置，测不出"停在上一轮"**）；
- 选型有没有越序：判据缺来源、方案早于判据、悬置没写解锁条件、说了要做实验却没有实验件……

它不判阶段、不推进、不拦讨论。

```bash
node scripts/check.mjs --root design/<slug>        # 人读
node scripts/check.mjs --root design/<slug> --json # 机器读
node scripts/check.mjs --root design/<slug> --map  # 顺手写出 map.md
node scripts/check.mjs --cwd .                     # 自动发现讨论根
node scripts/check.mjs --trees                     # 列出项目里的全部讨论根
```

退出码 0 = 齐（可能有警告），1 = 缺件。它同时是模块：`import { check, renderReport, buildMap, discoverRoots } from './scripts/check.mjs'`。

## 与上一版的关系

**v1** 是一台"阶段机"：S0–S7、每阶段出口条件、候选/定论两档、轮次纪要、全量重判、写入状态文件。一次实测暴露了它的代价——**机械的条例增长**（同一个决定写两遍）、**过早收敛**（四条并列的单点各推一遍就算完成，主干从未被问）、**门禁反过来牵着推演走**（为了过检查拼推演链）、**用词公文化**、**阶段完成感压过问题本身**。

**v1.5** 撤掉了那些机制，只留"文件组织 + 用语"，把进度交回给文件与编号。它的漏洞是**收不了尾**：循环里写了"概念必须生出下一个问题"，却没写"未定项必须被解决"——于是长出新问题成了每个节点的成绩，解决问题反倒没人要求，节点可以一路长下去。

这一版补上三件事：**先选一个核心并写下放弃代价**（避免给两个打架的目标同时打工）、**未定项必须被解决且不再增长**（节点可以无限长，摊子不可以）、**实验可以推翻理念、也可以判定需求不可行**（果实是一份文本加一批能跑的实验文件）。

**这一轮**接着补三件来自实际使用的事，核心押在**记录不过时**上：

- **公式里的每个量都要讲完**（它在系统里指什么／从哪观测到／单位或量级／怎么数；给不出"怎么数"的标「候选（待答）」），**从常用词借来的词要当场声明差在哪**——同名不同义是误解的主要来源：用户以为是你说的那个意思，其实是你定的那个意思；
- **概念第一次成形时走一遍**：一条具体输入，从进入到结束走完全程，补上「怎么落机制」（机制视角）之外的时间视角；
- **记录不过时**：结论被认下就**当轮写回文件**（写回清单），新会话或上下文被压缩后**先读 `map.md` → 最后一个节点 → `model.md`，再用三句话复述**让用户纠正；体检新增 `undecided.drift`（`undecided:` 与「## 未定项」条数不符）与 `map.drift`（**内容级**比对「现在停在／下一步」两行——`mtime` 测不出"停在上一轮"）；`map.md` 多一行「**下一步**」。**读者默认不是本行技术人**，技术词第一次出现要当场落地。

**方法本体只留一份。** persona 只带常驻契约（不变量、写回与接续、读者假定、最常写错的用语），第一行就把模型推到 `SKILL.md`；同一段话不再各层手抄。`selftest.mjs` 里有一条断言守着它：`references/` 每份都必须进 `SKILL.md` 的索引，两处的 `references/` 指针都不许悬空，persona 正文守在 7 KB 预算内——**曾经有一次给 skill 加了 `references/writing.md` 的指针，persona 那份没跟上**，这条断言就是从那次漂移来的。

旧形状的讨论根（`state.json` / `layers` / `concept`）**原样保留、可读、不迁移**；v1.5 形状（多个平权的需求线、`step:` 标六个循环位置、没有未定项）在体检器里同样读得懂、不报缺件。要按这一版继续，就在同一项目里新开一个讨论根，并在新 `seed.md` 里写一句「与已有树的关系」：继承了什么、推翻了什么。

## 出处与许可

提问纪律（一次一问、能从文件查到的不问人）取自 [grill-me](https://github.com/RobMitt/grill-me-skill) 的思路；把它最有害的一条——"每个问题都写出我的倾向"——**去掉了**：给了"选项 + 我的倾向"，讨论就变成"我给现成方案、用户盖章"。现在的形态是把张力摊开、把用户的理由要出来。
