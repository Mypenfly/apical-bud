# apical-bud（顶芽）

[English](README.en.md) | 中文

**把一句需求推演成抽象概念模型的记录规范。** 它只规定两件事：**文件怎么组织、词怎么用**——不规定每轮必须产出什么，也没有阶段、门禁与轮次纪要。文件是推演与论证的记录，不是进度报告。

```
seed.md ─► facts.md ─► derivation/ ─► model.md ─► build/ ─► handoff.md
 种子        事实与调研   推演点        顶芽        实现选型    交接件
 用户需求                (问题 ⇄ 结论)
 核心问题                     └──────── map.md（进度与概念图，工具生成）────────┘
```

## 它要解决什么

一次讨论最容易变成两种东西：**给现成方案**，或者**给流程交作业**。前者是"跳过推演直接谈理念"，后者是"按阶段生产文档"。这一版把两头都堵住：

- **推演是一个循环**：需求 → **拆词** → **逐项论证**（调研在这里）→ 立一个抽象理念 → 拿它倒回去解释需求与每一项 → 得出下一个结论 → 生出新问题 → 回到「拆」。一步的产物是**概念**，不是数字、不是清单。
- **拆的是需求自己的词**：名词问"由什么组成、怎么算"，形容词问"有哪些特征、怎么评价"。每一项写成一条需求线 `R-01`…，都要被论证、都要有推演点。
- **每一步都由前面已经写下的东西得出**，最前面的是用户的需求。`answers:`（回答哪一步生出的问题）、`from:`（拿哪些结论当前提，只放 `D-`）、`line:`（服务哪条需求线）是三种关系。
- **进度写在文件与编号里**：推演点一点一文件、按序编号，点内编号是 `Q-03.1`／`D-03.1`——**编号自带进度坐标**；`map.md` 里还有一张**需求线覆盖表**（哪条线推到哪、哪条一个点都没有）与一条**概念链**，新开一个会话只读它就接上。
- **用语被当作规范的一部分**：写"因为／所以／如果／反过来／代价是"，不写"阶段／门禁／出口条件／落盘／轮次／完成"。
- **提问是把张力摊开，不是给选项**：形态是"这两条不能同时成立，你放弃哪一条、为什么"，外加"我押哪条、我可能错在哪"。

## 一次推演怎么走

| 文件 | 装什么 |
|---|---|
| `seed.md` | 用户原话（只追加）、一句话需求、**需求线（拆词）**、**核心问题**、非目标、什么叫成了、被否的表述 |
| `facts.md` | `## F-001` 事实 + 出处 + 等级（E1 文档源码／E2 实测／E3 二手）+ 用途；末尾一节「没查的」 |
| `derivation/NN-<词>.md` | 一个推演点：问题／已知／推论／结论／反过来／生出的问题／用户 |
| `model.md` | 抽象概念模型（顶芽）：名字、一句话、组成、接缝与边界、确定了什么／还没确定什么、要落地必须先定的事 |
| `build/01-判据.md`、`02-方案.md`、`03-选型.md` | 判据先写、方案后看；淘汰者写拒绝理由与复活条件 |
| `handoff.md` | 交接件：自包含，可直接转交标准模式实现（含验收、第一件事、可复制的提示词） |
| `map.md` | 进度、需求线覆盖表、概念链——**工具生成，模型不手写** |
| `glossary.md` | 术语：`- **词**：一句人话定义`（附「曾用名」「不用的词」） |

一个推演点长这样（摘要，完整写法见 [`references/writing.md`](references/writing.md)）：

```markdown
---
point: 02
title: 该减少劣质还是增加优质
status: open
step: 立概念          # 循环位置：拆词／论证／立概念／倒回去解释／长出新结论／生出问题
line: R-02            # 在哪条需求线上
concept: 优质 / 劣质 token
answers: [Q-01.2]     # 在回答哪一步生出的问题
from: [D-01.1]        # 拿哪些结论当前提（只放 D-）
---
## 问题    Q-02.1 提高上下文密度，该从减少劣质片段入手，还是从增加优质片段入手？
## 已知    [事实 F-002] 能一眼认出的劣质特征只有浅层那几类；需要上下文才能判断的，人和模型都认不出。
## 推论    减少劣质要求先认出它，而"认出"本身更难；增加优质只需要在事情变坏时给出基于事实的判断。
## 结论    D-02.1 只做"增加优质"这一侧。放弃"清理已有上下文"。
## 反过来  若注入总是晚于错误的固化，这条不成立。
## 生出的问题  Q-02.2 谁来判断"将要固化"？（去向：待答）
```

**用户已经给了结论怎么办**：把它登记成"待推导的结论"，从需求正推一遍——推得到，它才被论证；推不到，它就是假设或竞争概念，并说清差在哪一跳。不许拿它当前提直接用。

## 体检（很轻）

只查**组成成分齐不齐**：种子四节在不在（含**需求线**——把需求里的词拆成 `R-01`…）、事实与术语表在不在、有没有推演点、推演点的「问题」「结论」空不空、模型与选型文件若存在是否成形。**其余一律只是警告**：

- 推演有没有偏：某条需求线一个点都没有、连着四个点都在同一条线上、连着几个点没有出现新概念；
- 锚有没有挂错：`from:` 里放了事实、点没写 `line:`／`step:`／`concept:`、编号指向不存在、第 2 个点与上一步无关；
- 选型有没有越序：判据缺来源、方案早于判据、悬置没写解锁条件……

它不判阶段、不推进、不拦讨论。

```bash
node scripts/check.mjs --root design/<slug>        # 人读
node scripts/check.mjs --root design/<slug> --json # 机器读
node scripts/check.mjs --root design/<slug> --map  # 顺手写出 map.md
node scripts/check.mjs --cwd .                     # 自动发现讨论根
node scripts/check.mjs --trees                     # 列出项目里的全部讨论根
```

退出码 0 = 齐（可能有警告），1 = 缺件。它同时是模块：`import { check, renderReport, buildMap, discoverRoots } from './scripts/check.mjs'`。

## 安装

**DSH（DeepSeek Harness）**：

```bash
git clone git@github.com:Mypenfly/apical-bud.git ~/.dsh/skills/apical-bud

# 可选：装上会话装配层（常驻身份、apical_check 工具、写守卫、状态横幅）
~/.dsh/skills/apical-bud/dsh-preset/install.sh
```

`dsh-preset/` 把两条规矩变成机制：`write`/`edit` 只允许写讨论根（`design/`），讨论不碰实现；`seed.md` 的「用户原话」只追加。细则见 [`dsh-preset/README.md`](dsh-preset/README.md)。

改完 skill 或 preset 之后记得跑一次 `install.sh`，并**新开一个会话**：persona 与 SKILL.md 在会话开始时注入。

**Claude Code / 其他兼容 SKILL.md 的宿主**：

```bash
git clone git@github.com:Mypenfly/apical-bud.git ~/.claude/skills/apical-bud
```

## 与上一版（v1）的关系

v1 是一台"阶段机"：S0–S7、每阶段出口条件、候选/定论两档、轮次纪要、全量重判、写入状态文件。一次实测暴露了它的代价——**机械的条例增长**（同一个决定写两遍）、**过早收敛**（四条并列的单点各推一遍就算完成，主干从未被问）、**门禁反过来牵着推演走**（为了过检查拼推演链）、**用词公文化**、**阶段完成感压过问题本身**。

这一版把那些机制整体撤掉，只留下"文件组织 + 用语"这一层规范，并把进度交回给文件与编号。旧形状的讨论根（`state.json` / `layers/` / `concept/`）**原样保留、可读、不迁移**；要按新形状继续，就在同一项目里新开一个讨论根，并在新 `seed.md` 里写一句「与已有树的关系」：继承了什么、推翻了什么。

## 出处与许可

提问纪律（一次一问、能从文件查到的不问人）取自 [grill-me](https://github.com/RobMitt/grill-me-skill) 的思路；这一版把它最有害的一条——"每个问题都写出我的倾向"——**去掉了**：实测里用户九次原样采纳主持人的倾向，讨论于是变成"我给现成方案、用户盖章"。现在的形态是把张力摊开、把用户的理由要出来。
